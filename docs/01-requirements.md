## 1. 背景と目的

Excel の数式言語は関数の入れ子が深くなるほど読み書きが難しく、VBA との間にも言語的な断絶がある。
本プロジェクトは、**セル数式とマクロを同一のオブジェクト指向言語（Smalltalk 風）で統一的に記述できる**
スプレッドシートを作ることで、次を狙う。

1. **一貫性** — `A1..A10 sum` のようなメッセージ送信で、数式もマクロも同じ語彙で書ける。
2. **合成可能性** — `select:` / `collect:` / `inject:into:` などのブロック付きメッセージで、
   関数の入れ子ではなくパイプライン的に集計を組み立てられる。
3. **AI 支援前提の設計** — Claude Code から MCP 経由でシートを読み書き・評価できるようにし、
   「この列を月別に集計して」といった自然言語の指示から数式・マクロを生成・検証できる。

### 1.1 「非目標」（本プロジェクトがやらないこと）

- Excel との完全な数式互換、`.xlsx` の完全な読み書き
- Smalltalk 処理系としての完全性（イメージ永続化、メタクラス階層、`become:` 等）
- リアルタイム共同編集、サーバー側でのマルチユーザー管理（将来検討）
- ピボットテーブル、グラフ描画（MVP 後の拡張候補）

## 2. 全体方針（確定事項）

| 論点 | 決定 | 理由 |
| --- | --- | --- |
| 言語の範囲 | **式言語サブセット**（メッセージ式・リテラル・ブロック・カスケード・代入・組み込みクラス群）。ユーザー定義クラスは対象外 | 表計算の数式／マクロ用途には十分で、処理系の実装量と学習コストのバランスが良い |
| AI 連携 | **MCP サーバー経由**。アプリが MCP サーバーを公開し、Claude Code がツールとしてシートを操作 | ローカル開発環境で自然言語操作を実現でき、API キー管理が不要 |
| 技術構成 | **TypeScript + フロント完結**（Vite / IndexedDB / ファイル入出力）。MCP サーバーのみ別プロセスの Node | バックエンド運用なしで動作し、配布が容易 |
| MVP | **計算コア先行**（パーサ → 評価器 → 依存グラフ → 再計算エンジンを CLI とテストで完成させ、その後 UI） | 言語仕様の検証を最速で回せ、テストが書きやすい |

## 3. 想定ユーザーとユースケース

### 3.1 ペルソナ

| # | ペルソナ | 動機 |
| --- | --- | --- |
| P1 | Smalltalk / オブジェクト指向に馴染みのある開発者 | Excel 数式のネストが苦痛。メッセージ式で表計算したい |
| P2 | 表計算の中〜上級ユーザー | VBA の代わりに読みやすいマクロ言語が欲しい |
| P3 | Claude Code 利用者 | 自然言語で集計ロジックを組み立て、結果を目で確認したい |

### 3.2 代表ユースケース

- **UC-1 数式入力**: セルに `= (B2..B13) sum` と入力し、合計を表示する。
- **UC-2 マクロ実行**: 「月次レポート整形」マクロを保存し、ボタン／コマンドパレットから実行する。
- **UC-3 AI による数式生成**: Claude Code に「C 列の税込金額を D 列に出して」と依頼 → MCP 経由で
  D 列に数式が設定され、再計算結果まで検証される。
- **UC-4 AI によるデバッグ**: `#Error` になっているセルを Claude Code が読み取り、原因を説明して修正する。
- **UC-5 データ入出力**: CSV を読み込み、計算後に CSV / JSON として保存する。

## 4. 用語定義

| 用語 | 定義 |
| --- | --- |
| ブック (Book) | シートの集合。保存単位 |
| シート (Sheet) | セルの二次元格子。名前を持つ |
| セル (Cell) | 値・数式・書式を持つ格子の要素。`A1` 形式で参照 |
| 範囲 (Range) | 連続したセルの矩形領域 |
| 数式 (Formula) | セルに紐づく**副作用のない**式。値を 1 つ返す |
| マクロ (Macro) | ブックに紐づく**副作用を許す**手続き。セルの書き換え等を行う |
| 評価器 (Evaluator) | 構文木を評価する処理系 |
| 依存グラフ | セル間の参照関係を表す有向グラフ。再計算順序の決定に使う |

## 7. アーキテクチャ方針

```
packages/
  core/        計算コア（DOM 非依存・MVP の主対象）
    lexer/     字句解析
    parser/    構文解析 → AST
    runtime/   評価器、組み込みクラス、ブロック、エラー
    model/     Book / Sheet / Cell / Range / 参照解決
    engine/    依存グラフ、トポロジカルソート、増分再計算
  cli/         コアを叩く REPL とバッチ評価。開発時のフィードバックループの基盤
  web/         UI（グリッド、数式バー、マクロエディタ）
  mcp/         MCP サーバー（core を import してツールを公開）
docs/          仕様・設計ドキュメント
```

依存方向は `core ← cli / web / mcp` の一方向のみ。`core` はブラウザ API に依存しない。
これは `packages/core/tsconfig.json` で DOM と `@types/node` を読み込まないことにより、
型検査で強制している（ADR-0001）。

`cli` は「動作確認用のおまけ」ではなく**開発基盤**である。開発中の Claude Code への
フィードバックは MCP ではなく CLI で回す（Bash から直接叩けるため速く確実）。
MCP はエンドユーザーが自然言語でシートを操作するための機能であり、M5 のままとする。

## 9. 未決の設計論点（次の議論対象）

| ID | 論点 | 案 |
| --- | --- | --- |
| D-1 | **範囲リテラルの記法**。Excel の `A1:B10` はキーワードメッセージのコロンと衝突する | (a) `A1..B10`（推奨。衝突なし・簡潔） / (b) `A1 to: B10` / (c) `Range from: #A1 to: #B10` / (d) `A1:B10` を字句解析で特別扱い |
| D-2 | **セル参照と変数名の区別**。`A1` は参照か識別子か | (a) `[A-Z]+[0-9]+` 形状を常にセル参照とみなし、その形の変数名を禁止（推奨） / (b) `@A1` のような接頭辞を付ける |
| D-3 | **マクロからのセル書き込み構文** | (a) `B14 := total`（読みやすい。参照への代入を特別扱い、推奨） / (b) `Sheet at: #B14 put: total`（Smalltalk として素直） / (c) 両方 |
| D-4 | **数式の値が自動的に範囲へ展開されるか**（スピル） | (a) MVP では展開しない（単一値のみ） / (b) 配列を返した場合に隣接セルへ展開 |
| D-5 | **文字列リテラルの引用符**。Smalltalk は `'...'` が文字列、`"..."` がコメント | Smalltalk 流を踏襲（Excel 慣れしたユーザーには注意喚起が必要） |
| D-6 | **空セルの値**。`nil` か `0` か空文字か | (a) `nil` とし、`sum` 等の集計では無視（推奨） |
| D-7 | **MCP サーバーとブラウザ UI の状態共有方式** | (a) MVP は MCP サーバー側をブックの正とし、UI は WebSocket で購読 / (b) MVP は UI と MCP を別ブックにし、ファイル経由で同期 |
| D-8 | **エラーの捕捉構文**。`on:do:` を入れるか | MVP では `ifError:` のみとし、例外クラス階層は入れない案 |
| D-9 | **数式の再帰**。数式から名前付きユーザー定義関数を呼べるか | MVP では不可。マクロのみ再帰可 |

## 10. 受け入れ基準（MVP）

MVP は次がすべて満たされた時点で完了とする。

1. CLI の REPL で、以下がすべて期待どおり評価される。
   ```smalltalk
   3 + 4 * 2                                   "→ 14（左から右）"
   (3 + 4) * 2                                 "→ 14"
   10 sqrt                                     "→ 3.1622..."
   #(1 2 3 4) inject: 0 into: [:a :b | a + b]  "→ 10"
   #(1 2 3 4) select: [:e | e > 2]             "→ #(3 4)"
   5 > 3 ifTrue: ['大'] ifFalse: ['小']         "→ '大'"
   ```
2. シートに対して次が成立する。
   - `A1`〜`A10` に 1〜10 を入れ、`B1` に `= A1..A10 sum` で 55 が出る。
   - `A3` を 100 に変えると `B1` が 145 に更新され、かつ `A1..A10` 以外のセルは再評価されない。
   - `C1` に `= C1 + 1` を入れると `#Circular` になり、他セルの計算は継続する。
3. マクロが動く。
   ```smalltalk
   | total |
   total := (B2..B13) sum.
   B14 := total.
   B15 := total / 12.
   ```
   実行後 `B14` `B15` が更新され、途中でエラーを起こしたマクロは何も書き込まずに巻き戻る。
4. Claude Code から MCP 経由で UC-3（自然言語での数式生成）と UC-4（エラー原因の説明と修正）が完遂できる。
5. 計算コアのテストカバレッジが行 80% 以上で、CI が緑。
