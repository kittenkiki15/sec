### 0.3 表記の約束

**文法は EBNF で書く。** 記法は次のとおり。

| 記法 | 意味 |
| --- | --- |
| `=` | 定義 |
| `,` | 連接 |
| `\|` | 選択 |
| `{ x }` | 0 回以上の繰り返し |
| `[ x ]` | 省略可能 |
| `( x )` | グループ化 |
| `"x"` | 終端記号 |
| `(* x *)` | 注釈 |

**値の表記**は、ゴールデンテストの期待値に書く形であり、評価結果を人間に見せるときの形でもある。

| 種別 | 表記 | 例 |
| --- | --- | --- |
| 整数 | 小数点を付けない | `42` `-5` |
| 小数 | 小数点を必ず付ける。指数表記は §6.1、**負のゼロも `0.0`** | `3.14` `1500.0` `1.0e-310` |
| 文字列 | `'` で囲む。内部の `'` は二重にする | `'abc'` `'It''s'` |
| シンボル | `#` を付ける | `#foo` `#at:put:` |
| 真偽値・nil | そのまま | `true` `false` `nil` |
| リテラル配列 | `#( ... )`。要素を空白 1 つで区切る | `#(1 'two' #three)` `#()` |
| セル | 保持する値の表記に従う（§4.2） | `1` `'abc'` |
| 範囲 | 正準形と同じ形（§4.3） | `A1 to: B10` |
| 区間 | 正準形と同じ形（§6.3） | `1 to: 5` |
| ブロック | `aBlock`。引数の数も本体も表記しない（§5.1） | `aBlock` |
| エラー | 種別のシンボルだけを書く | `#Syntax` `#DoesNotUnderstand` |

**小数の指数表記は [ADR-0017](adr/0017-float-exponent-notation.md) で定めた。**
指数表記を使うのは、値が 0 でなく**絶対値が `1e21` 以上、または `1e-6` 未満のとき**。
仮数には小数点を必ず付け、指数は小文字 `e` で正の符号は付けない（`1.0e-310`、`1.0e21`）。
**境界の数値に理論的な必然性は無い**が、一意に定めることを優先した（§6.1）。

**この表が定めるのは出力の形であり、ソースとして何を受理するかではない。**
受理する形は §1〜§3 の文法が定め、両者は一致しなくてよい
（例: `#(1'foo')` は受理され、`#(1 'foo')` と表示される）。

エラーの表記に文言や位置を含めないのは、**文言の変更でゴールデンテストが落ちるのを避ける**ため。
人間と AI に読める説明文は別に持つ（要件 F-8-3）。エラーの種別は要件 F-8-2 で定めた
`#Syntax` `#DoesNotUnderstand` `#TypeError` `#DivideByZero` `#Circular` `#Ref` `#Timeout`
`#Overflow` `#SubscriptOutOfBounds` の 9 つ（最後の 2 つは
[ADR-0013](adr/0013-non-finite-numbers.md) と [ADR-0014](adr/0014-subscript-out-of-bounds.md) で追加）。

数値の内部表現・精度・演算結果の型（整数と小数が混ざったときにどちらを返すか等）は
**§6.1 で定めた**（[ADR-0012](adr/0012-number-model.md)）。本節が定めるのは表記だけである。

## 1. 字句

### 1.1 文字と空白

ソースは Unicode のテキストとする。次の 4 つを**空白**として扱い、トークンの区切りにだけ使う。

```ebnf
whitespace = " " | "\t" | "\r" | "\n" ;
```

- 空白の**量**は意味を持たない。`3+4` と `3   +   4` は同じ式である。
- **改行は空白と同じ扱い**で、式は何行に跨っても良い。文の区切りではない（区切りは §7 の `.`）。
- コメント（§1.5）は空白と同じ扱いとする。

### 1.2 識別子

```ebnf
letter     = "a" | ... | "z" | "A" | ... | "Z" ;
digit      = "0" | ... | "9" ;
identifier = ( letter | "_" ) , { letter | digit | "_" } ;
```

- **大文字と小文字を区別する。** `foo` と `Foo` は別の識別子である。
- 日本語などの非 ASCII 文字は識別子に使えない。文字列リテラルとコメントの中でだけ使える。

#### セル参照の形は識別子にできない

**`[A-Z]+[0-9]+` の形（大文字だけの英字に続いて数字）は常にセル参照として解釈し、
識別子としては使えない**（[ADR-0007](adr/0007-range-cell-reference-assignment.md) D-2）。

```smalltalk
A1      "セル参照。識別子ではない"
AB12    "セル参照"
Abc123  "識別子。小文字を含むためセル参照の形ではない"
A       "識別子。数字が無いためセル参照の形ではない"
a1      "識別子。英字が小文字のためセル参照の形ではない"
```

セル参照の意味論は §4 で定める。この規則を §1 に置くのは、**字句解析の時点で
両者を区別できる**ようにするためである。

### 1.3 予約語

`true` `false` `nil` の 3 つ。識別子として使えない。
これらは §2.5 でリテラルとして定義する。

ユーザー定義クラス・メソッドを持たない言語であるため（要件 2 章）、
`self` `super` `thisContext` は予約しない。

### 1.4 セレクタ

```ebnf
unary selector  = identifier ;                                (* 末尾に ":" が付かないもの *)
keyword         = identifier , ":" ;
keyword selector = keyword , { keyword } ;
binary character = "+" | "-" | "*" | "/" | "\" | "~" | "<" | ">" | "="
                 | "@" | "%" | "|" | "&" | "?" | "," ;
binary selector = binary character , [ binary character ] ;
```

- **キーワードの識別子と `:` の間に空白を置けない。** `max:` は 1 つのトークンであり、
  `max :` は 2 つのトークンになる（構文エラー）。
  この規則は範囲の糖衣 `A1:B10` を一意に解析するためにも要る（ADR-0007 D-1）。
- **識別子の直後が `:=` なら代入として切り出す**（§7.3）。`a:=1` は `a` `:=` `1` の
  3 トークンであり、キーワード `a:` と二項の `=` には切らない。空白を空けた `a := 1` と
  意味が変わらない方を採った。Smalltalk-80 と同じ扱いである。
- **二項セレクタは 1 文字か 2 文字。** 3 文字以上は認めない。最長一致で切り出す。
- `|` は二項セレクタであると同時にブロックの引数区切りでもある。
  どちらになるかは構文上の位置で決まる（§5）。

### 1.5 コメント

```ebnf
comment = '"' , { character - '"' | '""' } , '"' ;
```

- `"` で始まり `"` で終わる。**改行を跨げる。**
- コメントの中に `"` を書くには二重にする（`""`）。
- コメントは空白と同じ扱いで、式の途中にも置ける。

```smalltalk
3 "ここはコメント" + 4     "→ 7"
3 + "引用符は "" と書く" 4  "→ 7"
```

閉じていないコメントは `#Syntax` エラーとする。

> 文字列が `'...'`、コメントが `"..."` という割り当ては Smalltalk の慣習に従う
> （要件 F-2-2 / F-2-11、未決論点 D-5 の推奨案）。Excel に慣れた利用者は文字列を
> `"..."` と書きがちなので、エラーメッセージで案内する（要件 F-8-3）。
> **文言そのものは本書では定めない**（§0.3、§3.8）。

### 1.6 トークンの一覧

字句解析器が返すトークンは次のとおり。

| トークン | 例 |
| --- | --- |
| 整数リテラル | `42` `-5` `1e3` |
| 小数リテラル | `3.14` `1.5e3` `2e-3` |
| 文字列リテラル | `'abc'` |
| シンボルリテラル | `#foo` `#at:put:` `#+` `#'hello world'` |
| 予約語 | `true` `false` `nil` |
| 識別子 | `total` `_tmp` |
| キーワード | `max:` |
| 二項セレクタ | `+` `//` `>=` |
| セル参照 | `A1`（§4） |
| 範囲 | `A1..B10` `A1:B10`（§4） |
| 区切り記号 | `(` `)` `[` `]` `#(` `.` `^` `:=` `\|` |

`[` `]` は §5、`.` `^` `:=` `|` は §7 で使う。

**カスケードの `;` はトークンにしない**（§7.9）。カスケードを入れないと決めたため、
どの文法にも現れない。書けば `#Syntax` である。

## 2. リテラル

対応するフィクスチャ: [`tests/golden/literals.txt`](../tests/golden/literals.txt)

```ebnf
literal = number literal
        | string literal
        | symbol literal
        | reserved literal
        | literal array ;
```

### 2.1 数値

```ebnf
digits           = digit , { digit } ;
unsigned integer = digits ;
unsigned decimal = digits , "." , digits ;
exponent         = "e" , [ "-" ] , digits ;
unsigned number  = ( unsigned decimal | unsigned integer ) , [ exponent ] ;
number literal   = [ "-" ] , unsigned number ;
```

- **小数点の両側に数字が要る。** `.5` と `5.` は小数ではない。
  後者を認めないのは、マクロの文区切り `.`（§7）と紛れるため（`5.` は「5」と文区切り）。
- **先頭の 0 は無視する。** `007` は `7`。桁を揃えて書けると都合が良いため。
- **指数の `e` は小文字だけ。** 大文字を認めないのは、`1E3` の `E3` が
  セル参照の形（§1.2）と衝突するため。`1E3` は `#Syntax` になる。
- **指数は仮数の種別を変えない。** 仮数が整数で指数が非負なら整数（`1e3` → `1000`）、
  仮数に小数点があるか指数が負なら小数（`1.5e3` → `1500.0`、`2e-3` → `0.002`）。
- 16 進などの基数表記（Smalltalk の `16rFF`）は本仕様に含めない。
- **整数のリテラルに桁数の上限は無い。小数のリテラルには倍精度の範囲がある**（§6.1）。
  `1e400` は整数なので書けるが、`1.0e400` は `#Overflow` になる。

#### 負のリテラルと二項の `-`

`-` は負のリテラルの一部にもなり、二項セレクタにもなる。EBNF だけでは決まらないため、
**字句解析に次の付帯規則を置く。**

> `-` が負のリテラルの一部になるのは、**直後が数字**であり、かつ
> **直前のトークンが一次式の終端でない**ときに限る。
> 一次式の終端とは、リテラル・識別子・セル参照・**範囲トークン（§4.3）**・`)`・`]` である。

```smalltalk
-5      "負のリテラル。直前にトークンが無い"
3 -4    "3 - 4 = -1。直前のトークン 3 が一次式の終端"
3 + -4  "3 + (-4) = -1。直前のトークン + は二項セレクタ"
3 - -4  "3 - (-4) = 7"
-5 abs  "5。受け手が負のリテラル"
```

**空白の有無で意味を変えない。** `3 -4` と `3 - 4` と `3-4` はすべて `-1` である。

### 2.2 文字列

```ebnf
string literal = "'" , { character - "'" | "''" } , "'" ;
```

- `'` で囲む。内部に `'` を書くには二重にする（`''`）。
- **改行を跨げる。** 改行はそのまま文字列の一部になる。
- 空文字列は `''`。
- 閉じていない文字列は `#Syntax` エラーとする。
- 円記号などによるエスケープは無い。`\n` は 2 文字の文字列である。

### 2.3 シンボル

```ebnf
symbol literal = "#" , ( identifier | keyword selector | binary selector | string literal ) ;
```

```smalltalk
#foo            "→ #foo"
#at:put:        "→ #at:put:"
#+              "→ #+"
#'hello world'  "→ #'hello world'。識別子にできない綴りは引用符で囲む"
```

**`#` の後ろは綴りとして読む。** `#A1` はシンボルであってセル参照ではない。
§1.2 の「`[A-Z]+[0-9]+` は常にセル参照」は**式の中で**両者を分ける規則であり、
シンボルの綴りには及ばない（`#A1` と `#'A1'` は同じシンボルである）。

同じ綴りのシンボルは常に同一のオブジェクトである（意味論は §6）。

### 2.4 リテラル配列

```ebnf
literal array = "#" , "(" , { array element } , ")" ;
array element = number literal
              | string literal
              | symbol literal
              | bare symbol
              | reserved literal
              | nested array ;
bare symbol   = identifier | keyword selector | binary selector ;
nested array  = [ "#" ] , "(" , { array element } , ")" ;
```

- **`#` を省いた裸の識別子はシンボルになる。** `#(foo bar)` は `#(#foo #bar)`。
- **裸のキーワードセレクタは、隣り合っている間だけ 1 つのシンボルになる。**
  `#(at:put:)` は 1 要素の `#(#at:put:)`、`#(at: put:)` は 2 要素の `#(#at: #put:)`。
  走査が文字を追う Smalltalk の実装と同じ切れ方であり、下の `#(12)` と `#(1 2)` の
  区別と同じ性質でもある。**`#` を付けた形は空白を挟めないので、この区別は起きない**
  （`#at:put:` は §2.3 の 1 つのトークン）。
- **入れ子の配列は `#` を省ける。** `#(1 (2 3))` は `#(1 #(2 3))`。
- 空の配列は `#()`。
- 要素は**リテラルだけ**で、式は書けない。`#(1 + 2)` は `#(1 #+ 2)` であり、`#(3)` ではない。
- **要素の間の空白は、隣接するとトークンが変わる場合にだけ必要**（§1.1）。
  `#(1 2)` は 2 要素、`#(12)` は 1 要素。`#(1'foo')` は空白が無くてもトークンが分かれるため
  受理し、`#(1 'foo')` と同じ 2 要素になる。
- `-` の扱いは §2.1 の付帯規則に従う。`#(1-2)` の `-` は直前が一次式の終端 `1` なので
  二項セレクタであり、裸のシンボルになる。したがって `#(1 #- 2)` の 3 要素。
- 閉じていない配列は `#Syntax` エラーとする。
- リテラル配列は**変更できない**（意味論は §6）。

実行時に式から配列を作る記法（Pharo の `{1. 2. 3}`）は本仕様に含めない。
必要になれば §6 の `Array` のセレクタで作る。

### 2.5 真偽値と nil

```ebnf
reserved literal = "true" | "false" | "nil" ;
```

`nil` は「値が無い」ことを表す唯一のオブジェクト。**空セルの値は `nil` である**
（[ADR-0010](adr/0010-empty-cell-value.md)、未決論点 D-6 の決定）。詳しくは §6.0。

## 3. メッセージ式

対応するフィクスチャ: [`tests/golden/messages.txt`](../tests/golden/messages.txt)、
[`tests/golden/precedence.txt`](../tests/golden/precedence.txt)

この言語の計算はすべて**メッセージ送信**である。演算子は無く、`3 + 4` も
「`3` に `+` というメッセージを引数 `4` 付きで送る」ことを意味する。

### 3.1 文法

```ebnf
expression         = keyword expression ;
keyword expression = binary expression , [ keyword argument , { keyword argument } ] ;
keyword argument   = keyword , binary expression ;
binary expression  = unary expression , { binary selector , unary expression } ;
unary expression   = primary , { unary selector } ;
primary            = literal
                   | identifier
                   | cell reference        (* §4.1 *)
                   | range token           (* §4.3。字句規則で切り出す 1 つのトークン *)
                   | block                 (* §5.1 *)
                   | "(" , expression , ")" ;
```

数式（セルに `=` で始まる値を入れたもの、要件 F-2-1）の本体は `expression` ちょうど 1 つである。
文の列・代入・`^` による返却はマクロの文法であり、§7 で定める。
**数式にこれらが現れたら `#Syntax` エラーとする**（要件 F-2-10、数式は副作用を持てない）。

### 3.2 単項メッセージ

引数を取らないメッセージ。受け手の右に識別子を置く。

```smalltalk
5 abs            "→ 5"
3 negated abs    "→ 3。左から順に送る"
2 squared squared "→ 16"
```

### 3.3 二項メッセージ

引数を 1 つ取るメッセージ。セレクタは 1〜2 文字の記号（§1.4）。

```smalltalk
3 + 4    "→ 7"
3 > 5    "→ false"
3 = 3    "→ true"
```

### 3.4 キーワードメッセージ

引数を 1 つ以上取るメッセージ。**複数のキーワードは連結して 1 つのセレクタになる。**

```smalltalk
3 max: 4              "セレクタは max:"
3 between: 1 and: 5   "セレクタは between:and: で、1 回の送信"
```

ここが Smalltalk を知らない利用者の落とし穴になる。

```smalltalk
3 max: 4 min: 2       "セレクタ max:min: への送信。そのようなセレクタは無いので"
                      "→ #DoesNotUnderstand"
(3 max: 4) min: 2     "→ 2。括弧で 2 つのメッセージに分ける"
```

**キーワードメッセージは括弧なしに入れ子にできない。** 引数の側にキーワードメッセージを
置きたければ括弧で囲む。

### 3.5 優先順位

対応するフィクスチャ: [`tests/golden/precedence.txt`](../tests/golden/precedence.txt)

| 順位 | 種別 | 結合 |
| --- | --- | --- |
| 1（最も強い） | 丸括弧 `( )` | — |
| 2 | 単項メッセージ | 左から右 |
| 3 | 二項メッセージ | 左から右 |
| 4（最も弱い） | キーワードメッセージ | — |

#### 二項メッセージに優先順位は無い

**`*` が `+` より強いということはない。左から順に評価する。**
Excel や一般的なプログラミング言語との最大の相違点であり、
利用者が最も戸惑うところである。

```smalltalk
3 + 4 * 2      "→ 14。(3 + 4) * 2 と読む"
2 * 3 + 4      "→ 10"
3 + (4 * 2)    "→ 11。Excel と同じ意味にしたければ括弧で書く"
```

比較や論理演算も二項メッセージなので、同じ順位で左から評価される。

```smalltalk
1 + 2 > 2      "→ true。(1 + 2) > 2 と読む"
```

#### 単項 > 二項 > キーワード

```smalltalk
2 * 3 squared          "→ 18。squared が先"
1 + 2 squared          "→ 5"
3 max: 1 + 4           "→ 5。1 + 4 が先"
1 + 4 max: 3           "→ 5"
2 max: 3 + 4 squared   "→ 19。4 squared → 3 + 16 → 2 max: 19"
1 + 2 * 3 squared      "→ 27。3 squared → (1 + 2) → 3 * 9"
```

### 3.6 評価順序

1. **受け手を先に評価する。**
2. 次に**引数を左から右へ**評価する。
3. 最後にメッセージを送る。

すべての引数は送信の前に評価される（先行評価）。
**この順序はエラーの伝播として観測できる**（§6.0）。
**遅延評価が必要な場合はブロックを引数に取る**（要件 F-2-9）。
`ifTrue:ifFalse:` などの条件式がそうで、§5 で定める。

数式の評価は決定的である（要件 F-4-4）。同じ入力からは常に同じ結果が得られ、
乱数や現在時刻は明示された API 経由でのみ扱う。

### 3.7 理解できないメッセージ

受け手がセレクタを理解しない場合、`#DoesNotUnderstand` エラーを値として返す。
例外は投げない。エラーは値の一種であり、上流のエラーは下流へ伝播する（要件 F-8-1）。

**複数のエラーが同時に生じたときどれが伝播するかは §6.0 で定める**
（[ADR-0011](adr/0011-error-propagation-order.md)）。評価順で最初に生じたものが返り、
それ以降は評価しない。

```smalltalk
3 foo     "→ #DoesNotUnderstand"
3 foo: 4  "→ #DoesNotUnderstand"
```

### 3.8 構文エラー

次はいずれも `#Syntax` エラーになる。

```smalltalk
3 +       "二項セレクタに右の項が無い"
+ 3       "二項セレクタに受け手が無い"
3 max:    "キーワードに引数が無い"
max: 3    "キーワードに受け手が無い"
(3 + 4    "閉じていない丸括弧"
()        "空の丸括弧は式ではない"
```

構文エラーは行・列の位置と、人間にも AI にも読める説明文を持つ（要件 F-8-3）。
**位置と文言はゴールデンテストの期待値には書かない**（§0.3）。

**位置と説明文は値に載らない。** 値が持つのは種別だけなので、**位置が違っても同じ
`#Syntax` である。** 載せると「同じ種別でも位置が違えば別の値か」を決めることになるが、
§6.0 が定めているのは「エラーはメッセージを受け取らない」ことだけである。
評価する側は**値と診断の組**を返し、診断を要る側（CLI・UI）だけが受け取る。
**診断が付くのは構文エラーだけ**で、実行時のエラーは位置を持たない。

### 3.9 本書で定めないもの

| 構文 | 扱い |
| --- | --- |
| カスケード `;` | **入れない**（§7.9）。どの文法にも現れず、書けば `#Syntax` |
| 代入 `:=` | **§7.3 で定めた**（マクロの文）。数式では `#Syntax` |
| 文区切り `.` と返却 `^` | **§7.2 で定めた**（マクロの文法）。数式では `#Syntax` |
| ブロック `[ ... ]` | §5 |
| セル参照・範囲 | §4 |
| 各クラスが理解するセレクタ | §6 |

## 4. セルと範囲

対応するフィクスチャ: [`tests/golden/references.txt`](../tests/golden/references.txt)、
[`tests/golden/ranges.txt`](../tests/golden/ranges.txt)

表計算に固有の記法（セル参照と範囲）と、**セルに打たれた内容の読み方**を定める。
記法そのものの判断は [ADR-0007](adr/0007-range-cell-reference-assignment.md) で
済んでいるので、ここではそれを文法として書き下ろす。

### 4.1 セル参照

```ebnf
column         = "A" | ... | "Z" , { "A" | ... | "Z" } ;
row            = digit , { digit } ;
cell reference = column , row ;
```

- **大文字の英字に続いて数字。** この形は §1.2 のとおり常にセル参照であり、識別子にはなれない。
- 列は複数文字でもよい（`AB12`）。行の桁数に制限は無い。
- **行は 1 始まり**（要件 F-1-3）。`A0` は形としてはセル参照だが、その行は存在しない。

#### 綴りから番地へ

**番地は「列の綴り」と「行の数値」の組であって、原文の綴りではない**
（[ADR-0020](adr/0020-cell-address-normalization.md)）。上の字句規則は形を定めるだけで、
**その綴りがどのセルを指すかは次のとおり読む。**

- **行は十進数として読む。** 前ゼロは番地に残らない。`A007` `A0007` `A7` は**同じ 1 つのセル**を指す。
- **行は任意精度の整数である。** 桁数に制限が無い以上、倍精度に収める理由が無い（ADR-0012 と同じ）。
- **列は綴りがそのまま番地になる。** `A` `AB` は 26 進ではなく**双射基数 26**（`Z` の次が `AA`）で、
  前ゼロにあたる綴りが存在しない。正規化する余地がそもそも無い。

```smalltalk
"A7 に 1 が入っているとき"
A007        "→ 1。A7 と同じセル"
A007..A9    "→ A7 to: A9。範囲の表記（§4.3）の両端も正規化した綴りで書く"
```

**`A0` は `#Ref` のまま**（§4.2）。行が 1 始まりであること（要件 F-1-3）は番地の正規化とは
別の規則であり、**正規化した結果が 0 なら解決できない**、と読む。`A000` も同じ。

### 4.2 セル参照が評価されるもの

**セル参照は `Cell` オブジェクトに評価される**（[ADR-0008](adr/0008-cell-value-delegation.md)）。

- `Cell` 自身は `value` と `to:`（§4.3）を理解する。
- **`Cell` が理解しないメッセージは、保持する値へ転送する。**
- 値の表記は、保持する値の表記に従う（§0.3）。

```smalltalk
"A1 に 1 が入っているとき"
A1          "→ 1。表記は保持する値に従う"
A1 value    "→ 1。Cell 自身が理解する"
A1 + 1      "→ 2。Cell は + を理解しないので値へ転送する"
```

委譲の結果、`Cell` に無いセレクタのエラーは**値が返す** `#DoesNotUnderstand` になる。

#### 引数に現れたセルも解決される

**転送は受け手だけの話ではない。** メッセージを送る直前に、次のとおり解決する。

1. 受け手が `Cell` で、そのセレクタを **`Cell` 自身が理解する**（`value` / `to:`）
   → 受け手も引数もそのまま送る。
2. **それ以外** → 受け手と引数のうち `Cell` であるものを、保持する値に置き換えてから送る。

```smalltalk
"A1 に 3、B1 に 4 が入っているとき"
A1 + B1     "→ 7。規則 2。3 + 4 として送られる"
1 + A1      "→ 4。規則 2。受け手がセルでなくても引数は解決される"
A1 to: B1   "→ A1 to: B1。規則 1。引数はセルのまま渡る"
```

**規則 2 が要るのは、委譲が受け手の側でしか起きないためである。** これが無いと
`A1 + B1` は `3 + <Cell>` となり、値どうしの演算にならない。逆に規則 1 が無いと、
`to:` の引数まで値に置き換わって範囲が作れなくなる。

**規則 2 の受け手の解決は、引数を評価するより前に行う。** §6.0 の伝播順序が
「受け手 → 引数を左から右 → 送信」と定めており、**受け手のセルが先に評価されるとは、
受け手の値がエラーなら引数に到達しないということである**（[ADR-0023](adr/0023-dependency-extraction.md)）。

```smalltalk
"A1 の数式が #DivideByZero になるとき"
A1 + (1 / 0)   "→ #DivideByZero。受け手のセルの値が先に決まる"
A1 + (2 foo)   "→ #DivideByZero。引数のエラーには到達しない"
A0 + (1 / 0)   "→ #Ref。存在しない参照も同じ順序に従う"
```

**規則 1 では解決しない**ので、`value` と `to:` の受け手は値を読まれない。
範囲がセルの値を読まないこと（§4.3）は、この違いによる。

#### `=` は値の比較になる

**`Cell` は `=` を定義しない。** 委譲の規則がそのまま働き、保持する値どうしの比較になる。

```smalltalk
"A1 に 1、A2 に 1 が入っているとき"
A1 = A2   "→ true。別のセルだが値が等しい"
A1 = 1    "→ true。セルとリテラルの比較も値で行う"
```

セルの同一性を比べる手段は**本書では定めない。** 数式で必要になる場面が無いため。
必要になったら専用のセレクタを足す（`=` の意味は変えない）。

#### 存在しない参照

解決できない参照は `#Ref` エラーを値として返す。

```smalltalk
A0       "→ #Ref。行は 1 始まり"
total    "→ #Ref。裸の識別子は解決できない"
```

**数式中の裸の識別子は解決できない。** 名前付き範囲（要件 F-1-8）は MVP の範囲外であり、
数式から参照できる名前が存在しないため。構文解析ではなく評価の時点で `#Ref` とするのは、
名前付き範囲が入れば同じ構文が解決できるようになるためである。

> ブロックの引数と一時変数は識別子として解決できる（§5.1）。この規則が及ぶのは、
> どこにも束縛されていない識別子である。

#### 循環参照

参照が巡っている場合は `#Circular` エラーを返す（要件 F-8-2）。自分自身を参照する場合も含む。

```smalltalk
"A1 が =A1、B1 が =A1 + 1 のとき"
A1   "→ #Circular"
B1   "→ #Circular。巡りに加わっていなくても、読めば伝わる（§6.0）"
```

**`#Circular` はセルの値であって、参照そのもののエラーではない**（`#Ref` とはここが違う）。
読まなければ生じないので、**循環しているセルからも範囲は作れる**（§4.3）。

検出の仕組みと再計算の順序は**本書では定めない。** 依存グラフの話であり、要件 F-4 に属する
（[ADR-0023](adr/0023-dependency-extraction.md)）。

### 4.3 範囲

**正準形は `A1 to: B10` で、`Cell>>to:` が `Range` を返す**（ADR-0007 D-1）。
これは通常のキーワードメッセージ送信であり、特別な構文ではない。

**糖衣は字句規則である。** 構文規則として書くと空白を禁じられないため、
範囲は**字句解析の段階で 1 つのトークンとして切り出す**（§1.6 のトークン一覧、
[ADR-0007](adr/0007-range-cell-reference-assignment.md) の影響）。

```ebnf
(* 字句規則。トークンの内部なので、空白もコメントも改行も挟めない（§1.1） *)
range token = cell reference , ( ".." | ":" ) , cell reference ;
```

- 切り出しは**最長一致**で行う。
- **トークンの内部に空白を挟めないことが、そのまま糖衣の空白規則になる。**
  `A1 .. B10` `A1.. B10` `A1 ..B10` はいずれも範囲トークンにならず `#Syntax`。
  コロン形式も同じ。コメント（`A1"c"..B10`）と改行も、§1.1 が空白と同じ扱いにしているため挟めない。
- `A1..B10` と `A1:B10` は**糖衣**であり、**構文解析の時点で
  `cell reference , "to:" , cell reference` の送信へ脱糖する。**
  このトークンは §3.1 の `primary` の選択肢 `range token` として式に現れる。
- 正準形 `A1 to: B10` は 3 つのトークンからなる通常のメッセージ式なので、
  通常の空白規則に従う（`A1 to:B10` と書ける）。

**AST に範囲専用のノードを作らない。** 糖衣は `to:` の送信に還元されるため、
意味論の定義が `to:` の 1 箇所で済む。

#### 空白規則が要る理由

区切り文字の前後に空白を許さないことで、**字句解析だけで範囲とキーワードメッセージが
一意に決まる。**

```smalltalk
A1:B10      "範囲。コロンの前後に空白が無い"
A1 max: B1  "キーワードメッセージ"
A1 max:B1   "キーワードメッセージ。max: は 1 つのキーワードトークン（§1.4）"
```

`A1:` がキーワードセレクタになる経路は存在しない。`A1` は識別子になれず（§1.2）、
組み込みセレクタはすべて小文字始まりだからである（ADR-0007 D-2）。

#### 両辺はセル参照でなければならない

糖衣の両辺はセル参照に限る。`3..5` `A1..5` はいずれも `#Syntax` である。
範囲の範囲（`A1..B2..C3`）も作れない。

> 数の区間（`1 to: 5`）は §6.3 で入れた（[ADR-0016](adr/0016-number-interval.md)）。
> **`to:` は受け手で行き先が分かれる。** 本節が定めるのはセル参照から範囲を作る記法で、
> 数への `to:` は `Interval` を作る。**逆向きの扱いも逆になる**（範囲は正規化、区間は空）。

#### 向きは正規化する

**右下から左上へ書いても同じ矩形を指す。**

```smalltalk
B10 to: A1   "→ A1 to: B10"
B1 to: A2    "→ A1 to: B2。行と列で向きが別々でも正規化する"
```

ドラッグの向きで結果が変わらない方が表計算の利用者の期待に沿う。Excel の `B10:A1` と同じである。

#### 範囲の表記

**評価した範囲は正準形と同じ `A1 to: B10` と表記する**（§0.3 の表に加える）。

糖衣で書いても表記は正準形になる。`range.delimiter` の設定（ADR-0007）で
読み方が揺れないようにするためであり、ゴールデンテストが設定に依存しなくなる。

#### 範囲はセルの値を読まない

範囲は座標の対でしかなく、**作るだけならセルに値が入っている必要はない。**
`to:` は `Cell` 自身が理解するため、委譲も起きない。

範囲の**中身**を扱うセレクタ（`sum` など）は §6.3 で定めた。
**空セルの値は `nil` と決まり**（[ADR-0010](adr/0010-empty-cell-value.md)）、
集計はそれを無視する。

**この違いは循環参照で見える**（§4.2）。矩形の大きさは値を読まずに決まるが、
中身を扱うセレクタは読む。

```smalltalk
"A1 が =A1 のとき"
A1..A3        "→ A1 to: A3。作るだけなら読まない"
A1..A3 size   "→ 3。要素の数は矩形から決まる"
A1..A3 count  "→ #Circular。nil でない要素を数えるので読む"
```

### 4.4 セルの内容

**セルが持つのは原文テキストである**（要件 F-5-1）。そこから何を読み取るかを 3 段で決める
（[ADR-0021](adr/0021-cell-content-interpretation.md)）。**本節だけは数式の外の話**で、
利用者がセルに打った文字列をどう解釈するかを定める。

| 順 | 条件 | 結果 |
| --- | --- | --- |
| 1 | 内容が `=` で始まる | 残りを**数式**として構文解析・評価する（要件 F-2-1） |
| 2 | 内容が §2 のリテラルちょうど 1 つとして読める | そのリテラルの値 |
| 3 | それ以外 | **内容をそのまま持つ文字列** |

```text
=A1 + 1     "数式。A1 の値に 1 を足したもの"
1           "整数の 1"
007         "整数の 7。リテラルの正規化は §2.1 に従う"
'abc'       "文字列の abc"
true        "真偽値の true"
#foo        "シンボルの foo"
#(1 2 3)    "配列"
-5          "整数の -5（§2.1 の負のリテラル）"
abc         "文字列の abc。リテラルとして読めない"
A1          "文字列の A1。セル参照はリテラルではない"
1 + 2       "文字列の '1 + 2'。リテラルが 1 つではない"
```

**同じ文字列に `'abc'` と `abc` の 2 通りの書き方が生まれることは受け入れる。**
利用者に引用符を強いる表計算は存在しない（ADR-0021）。

#### 段 1 は原文の 1 文字目だけを見る

**前後の空白を無視してから `=` を探すことはしない。**

```text
  =A1 + 1   "文字列の '  =A1 + 1'。数式ではない"
1 = 2       "文字列の '1 = 2'。= が途中にあっても数式にならない"
```

段 2 が前後の空白を無視する（下記）のに対して**段 1 だけが空白に厳しいのは、
数式かどうかが原文の見た目どおりに決まる方が事故が少ない**ためである。
無視する側にすると、**打ち間違えて入った空白が黙って数式を殺す。**
表計算の慣習とも揃う。

#### リテラルちょうど 1 つ

**§2 が定めるリテラルの構文に、内容全体が過不足なく一致することを言う。**
前後の空白は §1.1 のとおり無視する（`  1  ` は整数の 1）。

**「途中まで読めた分を採る」ことはしない。** `1 2` も `1 abc` も段 3 に落ちて文字列になる。
部分一致を許すと、`1 abc` が `1` になるか `'1 abc'` になるかを別途決めることになる。

**リテラルであって、式ではない。** `1 + 2` は式なので段 3 に落ちる。
`A1` も同じで、**セル参照はリテラルではない**（§2 に無い）。

#### リテラルとして読めても値がエラーになることがある

**段 2 に入るかどうかは構文で決まり、値がエラーかどうかは関わらない。**

```text
1.0e400     "→ #Overflow。§2.1 の形には合うが倍精度に収まらない（ADR-0013）"
```

これは文字列 `'1.0e400'` にはならない。**エラーもセルが持てる値である**（要件 F-1-2）。

#### 内容が空のセルは空セル

**内容が空文字列のセルは「空」であり、値は `nil`**（[ADR-0010](adr/0010-empty-cell-value.md)）。
段 2 にも段 3 にも落ちない。**空文字列を値として持つセルとは別物**で、後者は `''` と書いて作る。

**空白だけの内容は空セルではない。** 段 3 に落ちて文字列になる。

| 内容 | 値 |
| --- | --- |
| （何も打たれていない） | 空セル。`nil` |
| 空白だけ（`   `） | 空白 3 つの文字列 |
| `''` | 空文字列 |
| `'   '` | 空白 3 つの文字列 |

**空白だけの内容と `'   '` が同じ値になるのは段 3 の帰結**であって、
空白に特別な意味があるわけではない（`abc` と `'abc'` が同じ値になるのと同じ）。

**空かどうかは原文が空文字列かどうかで決まる。** 段 2 が前後の空白を無視するのは
§1.1 の字句の規則であって、**内容が空かどうかの判定ではない。**

### 4.5 本節で定めないもの

| 構文 | 扱い |
| --- | --- |
| 絶対参照 `$A$1` | 将来（要件 F-1-4、優先度 S） |
| 別シート参照 `Sales!A1` | 将来（要件 F-1-7、優先度 S） |
| 名前付き範囲 | 将来（要件 F-1-8、優先度 S）。入れば §4.2 の裸の識別子が解決できるようになる |

| 範囲が理解するセレクタ | §6 |
| 循環参照の検出と再計算順序 | 要件 F-4。本書は言語の定義に限る |
| 日付・時刻や数値フォーマットとして読むこと | 将来（要件 F-2-12、F-1-6）。入れば §4.4 の段が増える |

## 5. ブロックと条件式

対応するフィクスチャ: [`tests/golden/blocks.txt`](../tests/golden/blocks.txt)、
[`tests/golden/conditionals.txt`](../tests/golden/conditionals.txt)

### 5.1 ブロック

**ブロックは評価を遅らせるための値である。** 条件式（§5.2）はこれを土台にする。

```ebnf
block          = "[" , [ block arguments ] , expression , "]" ;
block arguments = ":" , identifier , [ ":" , identifier ] , "|" ;
```

- **引数は 0〜2 個**（要件 F-2-5）。3 個以上は `#Syntax`。
- 引数の並びの後ろに `|` を置く。`|` は二項セレクタでもあるが、
  ここに現れたものは引数の区切りである（§1.4）。
- ブロックの引数は、本体の中で識別子として解決できる。
- **同じ名前を二重に宣言できない。** `[:x :x | x]` は `#Syntax` である。
- **外側と同じ名前を内側で宣言できない。** `[:x | [:x | x] value: 1]` は `#Syntax` である。
  影になった名前は読み手が追えないためで、**この規則は開始記号で変わらない**（§7.5）。
  数式で宣言できる名前は引数だけなので、数式に現れるのはこの 2 つの形に限られる。

```smalltalk
[3 + 4] value                    "→ 7"
[:x | x * 2] value: 3            "→ 6"
[:x :y | x + y] value: 3 value: 4 "→ 7"
```

#### 数式のブロックの本体は式ちょうど 1 つ

**数式は副作用を持てない**（要件 F-2-10）。代入が書けない以上、一時変数を宣言しても
使い道が無く、文を並べる意味も無い。したがって数式のブロックの本体は式ちょうど 1 つとする。

```smalltalk
[:x | | t | t := x. t] value: 1  "→ #Syntax。代入は数式に現れない"
[| t | 1] value                  "→ #Syntax。一時変数の宣言も同じ"
[1. 2] value                     "→ #Syntax。文の区切りも同じ"
[^ 1] value                      "→ #Syntax。返却も同じ"
[]                               "→ #Syntax。本体が空も式ちょうど 1 つから外れる"
```

`[]` を `#Syntax` とするのは、§3.8 の「空の丸括弧は式ではない」と揃えたものである。

**マクロのブロックは文の列と一時変数を持てる**（要件 F-2-5）。その文法は §7 で定める。
本節が定めるのは数式に現れるブロックである。

#### 評価

`value` / `value:` / `value:value:` で評価する。引数の数が合わなければ `#TypeError`。

```smalltalk
[1 / 0] value        "→ #DivideByZero。value を送るまで中身は評価されない"
[:x | x] value       "→ #TypeError。引数が足りない"
[3] value: 1         "→ #TypeError。引数が多い"
```

#### ブロックの表記

**ブロックは `aBlock` と表記する**（§0.3 の表に加える）。引数の数も本体も表記しない。
本体の原文をそのまま書くと、空白の入れ方を変えただけでゴールデンテストが落ちるためである
（エラーの表記に文言を含めない理由と同じ）。

### 5.2 条件式

**条件式はすべて遅延評価である**（要件 F-2-9）。引数はブロックで渡し、
**選ばれなかった側は評価されない。**

| セレクタ | 受け手 | 返すもの |
| --- | --- | --- |
| `ifTrue:` | 真偽値 | 真なら引数を評価した値、偽なら `nil` |
| `ifFalse:` | 真偽値 | 偽なら引数を評価した値、真なら `nil` |
| `ifTrue:ifFalse:` | 真偽値 | 選ばれた側を評価した値 |
| `ifFalse:ifTrue:` | 真偽値 | 同上。順序を入れ替えた形も理解する |
| `ifNil:` | すべて | `nil` なら引数を評価した値、そうでなければ受け手 |
| `ifEmpty:` | 空になりうるもの | 空なら引数を評価した値、そうでなければ受け手 |

```smalltalk
true ifTrue: [1] ifFalse: [1 / 0]   "→ 1。偽の側は評価されない"
false ifTrue: [1]                   "→ nil"
nil ifNil: [0]                      "→ 0"
1 ifNil: [1 / 0]                    "→ 1。受け手が nil でないので引数は評価されない"
'' ifEmpty: ['空']                  "→ '空'"
'abc' ifEmpty: [1 / 0]              "→ 'abc'"
```

#### 引数はブロックでなければならない

**値を直接渡すことはできない。** 遅延評価が要件（F-2-9）であり、
値を渡せてしまうと先行評価になって要件を満たさないためである。

```smalltalk
true ifTrue: 1   "→ #TypeError"
```

#### 引数のブロックは引数を取らない

条件式はブロックを**引数なしで評価する。** したがって §5.1 の「引数の数が合わなければ
`#TypeError`」がそのまま当たり、引数を取るブロックを渡すと `#TypeError` になる。

```smalltalk
true ifTrue: [:x | x]   "→ #TypeError。引数の数が合わない"
nil ifNil: [:x | x]     "→ #TypeError。同じ"
```

**引数の数の検査は、ブロックを評価する経路すべてに当たる規則である。** `value:` の送信に
限った規則にすると、同じブロックが送り方によって別の意味を持つことになる。

**ただし選ばれなかった側は検査もされない。** 引数の型（ブロックかどうか）は引数そのものの
性質で、評価せずに見えるので常に検査する。**引数の数が合うかは、ブロックを評価するときに
初めて問題になる。**

```smalltalk
false ifTrue: [:x | x]   "→ nil。評価しないので引数の数は問われない"
false and: [:x | x]      "→ false。同じ"
false and: 1             "→ #TypeError。引数の型は短絡しても検査する"
```

#### 受け手が真偽値でない場合

`ifTrue:` などを理解しないので `#DoesNotUnderstand` になる。`nil` も同じで、
`nil` の判定は `ifNil:` で行う。

```smalltalk
3 ifTrue: [1]     "→ #DoesNotUnderstand"
nil ifTrue: [1]   "→ #DoesNotUnderstand"
```

#### 括弧なしに入れ子にできない

条件式もキーワードメッセージなので、§3.4 の規則がそのまま当てはまる。

```smalltalk
true ifTrue: [1] ifFalse: [2] ifTrue: [3]
   "→ #DoesNotUnderstand。セレクタ ifTrue:ifFalse:ifTrue: への送信になる"

(true ifTrue: [false] ifFalse: [true]) ifTrue: [1] ifFalse: [2]
   "→ 2。括弧で 2 つの送信に分ける"
```

### 5.3 本節で定めないもの

| 構文 | 扱い |
| --- | --- |
| 繰り返し（`do:` `collect:` など） | §6。ブロックを引数に取るコレクションのプロトコル |
| `whileTrue:` | **§7.6 で定めた。** 上限は要件 N-5 に従い、超過は `#Timeout`（§7.8） |
| `ifError:` | 未決論点 D-8。エラーの捕捉構文を入れるかがまだ決まっていない |
| マクロのブロック（文の列・一時変数） | **§7.5 で定めた** |
| 空になりうるものが何か | `String`（§6.2）と `Array` / `Interval`（§6.3）。`Range` は空にならない |

## 6. 組み込みクラスとセレクタ

対応するフィクスチャ: [`tests/golden/errors.txt`](../tests/golden/errors.txt)、
[`tests/golden/numbers.txt`](../tests/golden/numbers.txt)

§1〜5 は「どう書くか」を定めた。本節は**何を書けるか**、つまり数式から使えるオブジェクトと、
それぞれが理解するメッセージを定める。

**本節は分量が大きいため、クラスごとに分けて書き進めている。**

| 項 | 内容 | 状態 |
| --- | --- | --- |
| §6.0 | 共通の規則（エラーの区別・伝播順序・空セル） | 確定 |
| §6.1 | `Number` | 確定 |
| §6.2 | `String` / `Boolean` / `Symbol` / `nil` | 確定 |
| §6.3 | `Array` / `Range` / `Interval` / `Cell` | 確定 |
| §6.4 | 本節で定めないもの | 確定 |

### 6.0 共通の規則

#### 値の分類

数式の評価結果は、次のいずれかである。

| クラス | 何を表すか | 定める場所 |
| --- | --- | --- |
| `Number` | 整数と小数（§6.1） | §6.1 |
| `String` | 文字列 | §6.2 |
| `Boolean` | `true` / `false` | §6.2 |
| `Symbol` | `#foo` などのシンボル | §6.2 |
| `nil` | 「値が無い」ことを表す唯一のオブジェクト（§2.5） | §6.2 |
| `Array` | リテラル配列と `collect:` の結果 | §6.3 |
| `Range` | セルの矩形（§4.3） | §6.3 |
| `Interval` | 数の並び（`1 to: 5`） | §6.3 |
| `Cell` | セル参照の評価結果（§4.2） | §6.3 |

**エラーも値である**（要件 F-8-1）。ただしエラーはメッセージを受け取らない。
エラーになった時点で評価が打ち切られるためで、詳しくは後述する。

#### `#DoesNotUnderstand` と `#TypeError` の区別

**この 2 つは別物であり、混同すると仕様が読めなくなる。**

| エラー | いつ出るか |
| --- | --- |
| `#DoesNotUnderstand` | **受け手**がそのセレクタを持たない |
| `#TypeError` | 受け手はセレクタを持つが、**引数**の型が合わない |

```smalltalk
1 + 'abc'    "→ #TypeError。Number は + を持つが、文字列は足せない"
'abc' + 1    "→ #DoesNotUnderstand。String は + を持たない"
```

以降の表で「エラー」の欄が空なら、そのセレクタは引数の型で失敗しないという意味である。

#### 検査の順序

1 回の送信の中で複数のエラーが同時に該当しうる。**次の順に検査し、最初に当たったものを返す。**

| 順 | 検査 | エラー |
| --- | --- | --- |
| 1 | 受け手がセレクタを持つか | `#DoesNotUnderstand` |
| 2 | 引数の型が合うか | `#TypeError` |
| 3 | 演算が定義されるか（除数が 0 でない／添字が範囲内） | `#DivideByZero` / `#SubscriptOutOfBounds` |
| 4 | 結果を表せるか（§6.1 の変換と範囲） | `#Overflow` |

**「その演算が成り立つか」を先に、「値を表せるか」を後に見る。**

```smalltalk
1e400 / 0.0   "→ #DivideByZero。#Overflow ではない。0 で割ったことの方が原因として正確"
```

これは**1 回の送信の中の順序**であり、受け手と引数のどちらを先に評価するかを定めた
伝播順序（次項）とは別のものである。送信を伴わないエラー —— 構文エラー、
セル参照の `#Ref` や `#Circular`、リテラルそのものが表せない `1.0e400` の `#Overflow` ——
はこの表の外で、送信に至る前に決まる。

#### エラーの伝播順序

**式の評価は §3.6 の順序（受け手 → 引数を左から右 → 送信）で進み、
最初に生じたエラーがその式全体の値になる。それ以降は評価しない**
（[ADR-0011](adr/0011-error-propagation-order.md)）。

**エラーの種別に強弱は無い。** 決めるのは順序だけである。

```smalltalk
(3 foo) + (1 / 0)   "→ #DoesNotUnderstand。受け手が先"
(1 / 0) + (3 foo)   "→ #DivideByZero。入れ替えれば結果も入れ替わる"
```

とくに**引数は送信より先に評価される**。セレクタを理解しないと分かるのは送信のときなので、
引数のエラーの方が先に出る。

```smalltalk
3 foo: (1 / 0)   "→ #DivideByZero。#DoesNotUnderstand ではない"
3 foo: 1         "→ #DoesNotUnderstand。引数が正常なら送信まで進む"
```

エラーに更にメッセージを送ろうとしても、そこで既に打ち切られている。

```smalltalk
(1 / 0) abs        "→ #DivideByZero"
(1 / 0) abs squared "→ #DivideByZero。エラーは「セレクタを理解しない値」には変わらない"
```

構文エラーは評価より前に決まるため、**常に実行時のエラーより先に出る。**
評価されないブロックの中のエラーは、そもそも生じない（§5.2）。

```smalltalk
(1 / 0) +                            "→ #Syntax"
true ifTrue: [1] ifFalse: [1 / 0]    "→ 1"
[1 / 0]                              "→ aBlock。作るだけでは評価されない"
```

#### 空のセル

**空セルの値は `nil` である**（[ADR-0010](adr/0010-empty-cell-value.md)、未決論点 D-6 の決定）。
集計セレクタは `nil` の要素を無視する（§6.3）。

委譲（§4.2）に例外は無いので、**空セルを含む算術はエラーになる。**

```smalltalk
"A1 が空のとき"
A1 + 1   "→ #DoesNotUnderstand。nil は + を理解しない"
1 + A1   "→ #TypeError。Number は + を理解するが、引数が nil"
```

Excel は両方 `1` を返すため、**ここは意図的な乖離である。** 入力漏れが黙って 0 として
計算されないことを優先した。まとめて足したい場合は `A1..A10 sum` を使う。

### 6.1 Number

対応するフィクスチャ: [`tests/golden/numbers.txt`](../tests/golden/numbers.txt)

#### 数のモデル

**数は整数と小数の 2 種である**（[ADR-0012](adr/0012-number-model.md)）。

| | 内部表現 | 表記（§0.3） |
| --- | --- | --- |
| 整数 | **任意精度**。桁数に上限を設けない | 小数点を付けない（`42`） |
| 小数 | **IEEE754 倍精度** | 小数点を必ず付ける（`3.14`）。極端な大きさは指数表記（`1.0e-310`） |

- **整数と小数が混ざる演算は小数を返す**（伝染）。`1 + 2.0` → `3.0`
- **比較は値で行う。** `1 = 1.0` は `true`
- 整数に上限が無いのは、表計算では ID や金額の桁が倍精度の安全域（2^53）を
  超えることがあり、**黙って桁が落ちるのが最も危険**だからである
- 小数は倍精度なので、**丸め誤差はそのまま現れる。** `0.1 + 0.2` → `0.30000000000000004`
- **負のゼロは値としては残るが、表記は `0.0` とする。** `-0.0` は §2.1 の文法で書け、
  `0.0 * -1` でも生じる。値は IEEE754 のままなので `0.0 = -0.0` は `true` である。
  表記を分けないのは、**ゴールデンテストが符号の違いだけで落ちるのを避ける**ためで、
  エラーの表記に文言を含めない理由（§0.3）と同じ。整数の `0` に符号は無い

#### 変換と範囲

整数は桁数に上限が無く、小数には倍精度の範囲がある。**両者をつなぐ規則を定める**
（[ADR-0013](adr/0013-non-finite-numbers.md)）。

**小数が必要になった時点で、被演算子を小数へ変換する。** 結果を正確に求めてから
変換するのではない。

これは**結果の表現を決める段階の話**であって、演算が成り立つかどうかの検査より
先に来るわけではない。除数が 0 なら、変換を試みる前に `#DivideByZero` になる（§6.0）。

**変換できる範囲で桁が落ちるのは、エラーではない。**

```smalltalk
9007199254740993 + 0.0   "→ 9007199254740992.0。2^53 + 1 は倍精度で表せない"
9007199254740993 + 1     "→ 9007199254740994。整数どうしなら正確"
```

**小数として求める値が有限の倍精度で表せないときは `#Overflow`。** 非有限値
（`Infinity` `NaN`）はこの言語に存在しない。だから `rounded` / `truncated` が
常に整数を返す規則が保たれる。

**整数として求まる値に範囲の制限は無い。** 制限がかかるのは小数を経由する場合だけである。

**返り値が数でない演算は、そもそも変換を必要としない。** 比較（`<` `=` `between:and:`）は
真偽値を返すので、大きさを比べるだけで済む。`min:` / `max:` も受け手か引数をそのまま返す。

```smalltalk
1e400 > 1.0     "→ true。#Overflow ではない"
1.0 min: 1e400  "→ 1.0"
```

```smalltalk
1e400 / 1e399    "→ 10。指数は仮数の種別を変えない（§2.1）ので 1e400 は整数。"
                 "  整数のままなら範囲の制限は無い"
1e400 / 3        "→ #Overflow。割り切れないので小数が要る"
1e400 + 0.0      "→ #Overflow。混在演算でも変換が起きる"
1.0e400          "→ #Overflow。小数のリテラルそのものが範囲を超える"
1.0e308 * 10     "→ #Overflow。小数どうしの演算でも起きる"
1e400 sqrt       "→ #Overflow。結果の 1e200 は表せるが、受け手の変換が先に起きる"
```

#### 下側は丸めであってエラーではない

**小さすぎて表せない値は `0.0` に丸める。`#Overflow` にはしない。**

```smalltalk
1e-400                "→ 0.0。指数が負なので小数（§2.1）"
1.0e-300 * 1.0e-100   "→ 0.0"
-1e-400               "→ 0.0。符号は保つが負のゼロの表記は 0.0"
```

**上側と非対称なのは、丸め先があるかどうかが違うため。** 下側には `0.0` という
有限の倍精度が待っているが、上側には丸め先が無い。サブノーマル（`1.0e-310` など）は
表せるので、精度は落ちるがそのまま返る。`0` には潰れない。

**エラーにするのは「表せない」場合だけで、「精度が落ちる」場合ではない。**

#### 算術

| セレクタ | 引数 | 返り値 | エラーになる条件 |
| --- | --- | --- | --- |
| `+` `-` `*` | 数 | 数 | 引数が数でなければ `#TypeError` |
| `/` | 数 | **両方が整数で割り切れるなら整数、それ以外は小数** | 引数が数でなければ `#TypeError`。0 なら `#DivideByZero`（変換より先に判定する。§6.0） |
| `//` | 数 | 整数（床除算） | 同上。小数が混ざれば商を小数で求めるので `#Overflow` がありうる |
| `\\` | 数 | 数（剰余） | 同上。剰余は商を経由する |
| `abs` | — | 数 | — |
| `negated` | — | 数 | — |
| `squared` | — | 数 | — |
| `sqrt` | — | **常に小数** | 受け手が負なら `#Overflow`。受け手を小数へ変換できなければ `#Overflow` |
| `rounded` | — | **常に整数** | — |
| `truncated` | — | **常に整数** | — |
| `min:` `max:` | 数 | 数 | 引数が数でなければ `#TypeError` |

**`#Overflow` になるのは、小数として求める値が有限の倍精度で表せないときである**
（上の「変換と範囲」）。`1.0e200 squared` のようにエラー欄が空のセレクタでも起きる。
**整数として求まる値に範囲の制限は無い。** 表の「エラーになる条件」欄はこれを繰り返さない。

**`/` の返り値の型は、両辺の型と割り切れるかどうかで決まる。**
整数を返すのは**両方が整数で、かつ割り切れる**場合だけである。片方でも小数なら、
割り切れても小数になる（混ざれば小数という一般規則がそのまま効く）。

```smalltalk
6 / 3     "→ 2。割り切れるので整数"
7 / 2     "→ 3.5"
6.0 / 3   "→ 2.0。片方が小数なら、割り切れても小数"
1 / 0     "→ #DivideByZero"
```

**`//` は床除算で、商は負の無限大の側へ丸める**（Smalltalk-80）。
剰余 `\\` の符号は除数に合わせ、`self = (self // n) * n + (self \\ n)` が常に成り立つ。

```smalltalk
7 // 2    "→ 3"
-7 // 2   "→ -4。-3 ではない"
-7 \\ 2   "→ 1"
7 \\ -2   "→ -1"
```

**整数を返すのは `//` だけで、`\\` は小数を返しうる**（`7.5 \\ 2` → `1.5`）。
ただし**どちらも範囲の制限を免れるわけではない。** 受け手と引数がどちらも整数なら
整数演算のまま求めるので上限は無い。**小数が混ざる場合は商を小数で求めてから床を取る**ので、
そこで範囲を超えれば `#Overflow` になる。`\\` は同じ商を経由するため、同じ条件で
`#Overflow` になる。

```smalltalk
1e400 // 1e399        "→ 10。整数どうしなので整数演算のまま"
1.0e308 // 1.0e-300   "→ #Overflow。商 1.0e608 を小数で求められない"
1.0e308 \\ 1.0e-300   "→ #Overflow。剰余は商を経由する"
```

**`sqrt` は常に小数を返す。** 一般に無理数になるためで、`4 sqrt` も `2.0` である。
負の数の平方根は実数の範囲に無いので `#Overflow` とする（[ADR-0013](adr/0013-non-finite-numbers.md)）。

**`rounded` は端数がちょうど半分なら大きい側へ丸める**（Smalltalk-80 の `rounded`）。
`truncated` は 0 の側へ落とす。

```smalltalk
2.5 rounded    "→ 3"
-2.5 rounded   "→ -2。大きい側なので -3 ではない"
-3.7 truncated "→ -3。0 の側なので -4 ではない"
```

#### 比較

| セレクタ | 引数 | 返り値 | エラーになる条件 |
| --- | --- | --- | --- |
| `<` `<=` `>` `>=` | 数 | 真偽値 | 引数が数でなければ `#TypeError` |
| `between:and:` | 数、数 | 真偽値 | いずれかが数でなければ `#TypeError` |
| `=` `~=` | 任意 | 真偽値 | **なし** |

比較は真偽値を返すので、**大きな整数と小数が混ざっても `#Overflow` にならない**
（上の「変換と範囲」）。

**`=` と `~=` は型が違ってもエラーにならない。** 等しくないだけである。
比較できないものを比較するのは誤りではなく、`nil` や文字列と突き合わせる場面が普通にある。

```smalltalk
1 = 'abc'   "→ false"
1 = nil     "→ false"
1 < 'abc'   "→ #TypeError。大小は型が揃っていないと決まらない"
```

**`min:` と `max:` は `<` と `>` で定義する。**

```smalltalk
"min:  →  self < arg ifTrue: [self] ifFalse: [arg]"
"max:  →  self > arg ifTrue: [self] ifFalse: [arg]"
```

**値が等しければ比較が偽になるので、引数の側を返す**（Smalltalk-80）。整数と小数は
値で比較する（`1 = 1.0` は `true`）ため、**等しくても型が違うことがあり、
そのとき返り値の型は引数に従う。**

```smalltalk
1 min: 1.0        "→ 1.0。引数を返す"
1.0 max: 1        "→ 1"
(1 min: 1.0) + 0  "→ 1.0。返り値の型は後続の演算で観測できる"
```

規則を別に書かず定義から導けるようにしたのは、**「等しいときは受け手」といった
但し書きを増やさないため**である。

**`between:and:` の境界は含む。逆向きの区間は常に `false` になる。**
範囲（§4.3）が逆向きを正規化するのと**異なる**ので注意する。

```smalltalk
1 between: 1 and: 5   "→ true"
3 between: 5 and: 1   "→ false。正規化しない"
```

### 6.2 String / Boolean / Symbol / nil

対応するフィクスチャ: [`tests/golden/strings.txt`](../tests/golden/strings.txt)、
[`tests/golden/booleans.txt`](../tests/golden/booleans.txt)

#### String

**添字は 1 起点**（Smalltalk-80 と Excel のどちらもそう）。したがって **`0` は常に範囲外**で、
範囲外は `#SubscriptOutOfBounds` になる（[ADR-0014](adr/0014-subscript-out-of-bounds.md)）。

**文字型は持たない。** 要件 F-2-7 の組み込みクラスに文字が無いため、`indexOf:` は
**部分文字列**を取る。1 文字を取り出したい場合は `copyFrom:to:` を使う。

**ソースは Unicode のテキストであり**（§1.1）、非 ASCII の文字列リテラルは保持・比較・
連結できる。**未決なのは次の 2 点だけ**で、付録 B に送る。

1. **`size` と添字が何を 1 と数えるか**（コードポイントか書記素クラスタか）
2. **`asUppercase` / `asLowercase` が ASCII 外の文字をどう写すか**

したがって**本項の表が定める挙動のうち、非 ASCII で結果が変わりうるのは `size`・添字・
大文字小文字の変換だけ**である。連結や比較は「何を 1 文字と数えるか」に依存しない。
`asUppercase` / `asLowercase` は**英字以外をそのまま返す**（`'a1!' asUppercase` → `'A1!'`）。

| セレクタ | 引数 | 返り値 | エラーになる条件 |
| --- | --- | --- | --- |
| `,` | 文字列 | 文字列 | 引数が文字列でなければ `#TypeError` |
| `size` | — | 整数 | — |
| `isEmpty` | — | 真偽値 | — |
| `asUppercase` `asLowercase` | — | 文字列 | — |
| `indexOf:` | 文字列 | 整数（見つからなければ `0`） | 引数が文字列でなければ `#TypeError` |
| `copyFrom:to:` | 整数、整数 | 文字列 | 整数でなければ `#TypeError`。範囲外なら `#SubscriptOutOfBounds` |
| `asNumber` | — | 数、または `nil` | 倍精度に収まらない小数なら `#Overflow` |
| `=` `~=` | 任意 | 真偽値 | **なし** |

**`indexOf:` は見つからなければ `0` を返す**（Smalltalk-80）。添字が 1 起点なので、
`0` は「ありえない位置」として機能する。空文字列は常に先頭で見つかる。

```smalltalk
'abcd' indexOf: 'bc'   "→ 2"
'abc' indexOf: 'z'     "→ 0"
'abc' indexOf: ''      "→ 1"
```

**`copyFrom:to:` は `to` が `from - 1` に等しいときだけ空文字列を返す**（Smalltalk-80）。
それより小さければ範囲外である。

```smalltalk
'abcde' copyFrom: 2 to: 4   "→ 'bcd'"
'abc' copyFrom: 2 to: 1     "→ ''。to が from - 1"
'abc' copyFrom: 3 to: 1     "→ #SubscriptOutOfBounds"
'abc' copyFrom: 0 to: 2     "→ #SubscriptOutOfBounds。1 起点"
'abc' copyFrom: 1 to: 4     "→ #SubscriptOutOfBounds"
```

**`asNumber` が受理するのは §2.1 の数値リテラルの形ちょうど**であり、読めなければ `nil` を
返す。エラーにはしない。**新しい規則を作らず §2.1 を再利用する**ことで、リテラルとして
書ける形と文字列から読める形が常に一致する。

```smalltalk
'42' asNumber      "→ 42"
'1e3' asNumber     "→ 1000。§2.1 の指数の規則に従う"
'1E3' asNumber     "→ nil。§2.1 が大文字の E を拒む"
' 42' asNumber     "→ nil。前後の空白があると形が一致しない"
'5.' asNumber      "→ nil。§2.1 が小数として認めない"
'abc' asNumber     "→ nil"
```

`nil` が返るため、既定値は `ifNil:` で与えられる（`'abc' asNumber ifNil: [0]`）。

**形には合うが倍精度に収まらない小数は `#Overflow` である。** 「読めなかった」のではなく、
**リテラルとして書いたときと同じ値になる**（§2.1、[ADR-0013](adr/0013-non-finite-numbers.md)）。
再利用しているのは形の規則だけでなく、値の作り方も含む。**整数には桁数の上限が無い**ので、
指数が大きくてもそのまま整数になる。

```smalltalk
'1.0e400' asNumber   "→ #Overflow。リテラル 1.0e400 と同じ"
'1e400' asNumber     "→ 10 の 400 乗。整数に桁数の上限は無い"
```

**空になりうるのは `String` である**（§5.2 の `ifEmpty:` の受け手。`Array` と `Range` は
§6.3 で定める）。

#### Boolean

| セレクタ | 引数 | 返り値 | エラーになる条件 |
| --- | --- | --- | --- |
| `&` `\|` | 真偽値 | 真偽値 | 引数が真偽値でなければ `#TypeError` |
| `and:` `or:` | ブロック | 真偽値 | 引数がブロックでなければ `#TypeError` |
| `not` | — | 真偽値 | — |
| `isTrue` | — | 真偽値 | **なし**。すべての値が理解する |
| `=` `~=` | 任意 | 真偽値 | **なし** |

**`&` と `|` は先行評価、`and:` と `or:` は遅延評価**である。引数は送信の前に評価される
（§3.6）ため、`&` の受け手が `false` でも引数のエラーは表に出る。

```smalltalk
false & (1 / 0)     "→ #DivideByZero。先行評価"
false and: [1 / 0]  "→ false。選ばれないので評価されない"
true or: [1 / 0]    "→ true"
```

**`and:` / `or:` の引数がブロックでなければ `#TypeError`** とするのは、§5.2 の条件式と
同じ理由（値を渡せると先行評価になり、要件 F-2-9 を満たさない）による。

#### `isTrue` はすべての値が理解する

**受け手が `true` のときだけ `true`** で、それ以外はすべて `false` である
（[ADR-0022](adr/0022-is-true.md)）。`isNil` / `notNil` と同じ理由——
**受け手を選ばずに「真か」を尋ねられる必要がある。**

```smalltalk
true isTrue    "→ true"
false isTrue   "→ false"
nil isTrue     "→ false。空セルの値（ADR-0010）"
1 isTrue       "→ false。真偽値でない値は真ではない"
'true' isTrue  "→ false"
```

**これは「`false` 以外を真とみなす」規則ではない。** 条件として読む側の規則は変わらず、
真偽値でなければ `#TypeError` または `#DoesNotUnderstand` のままである（§5.2、§6.3、§7.6）。

```smalltalk
1 ifTrue: ['真']          "→ #DoesNotUnderstand。受け手が真偽値でない"
1 and: [true]             "→ #DoesNotUnderstand"
#(1 2) select: [:x | x]   "→ #TypeError。ブロックの値が真偽値でない"
```

**`isTrue` は明示的な問い合わせであって、暗黙の変換ではない。** 尋ねた場所で答えるだけで、
**尋ねていない場所で値が真偽値として扱われることはない。**

**`=` を理解する受け手では `= true` と同じ答えになる。** 新しい意味論を持ち込んでいない
ことが、ここで確かめられる。**ブロックだけが例外である**——ブロックは `=` を持たない
（§5.1）ので、受け手にすると `#DoesNotUnderstand` になる。

```smalltalk
[1] isTrue    "→ false。すべての値が理解する"
[1] = true    "→ #DoesNotUnderstand。ブロックは = を持たない"
```

**主な用途はセルを条件にすることである**（§6.3）。

条件式（`ifTrue:` `ifFalse:` など）は §5.2 で定めた。

#### Symbol

| セレクタ | 引数 | 返り値 | エラーになる条件 |
| --- | --- | --- | --- |
| `=` `~=` | 任意 | 真偽値 | **なし** |

**シンボルと文字列は別のクラスであり、両向きとも等しくない。**

```smalltalk
#foo = #foo    "→ true"
#foo = 'foo'   "→ false"
'foo' = #foo   "→ false"
```

数の `1 = 1.0` が `true` なのは整数と小数が同じ「数」だからであり、**クラスをまたいだ
同一視とは別の話**である。Smalltalk の実装には `#foo = 'foo'` と `'foo' = #foo` で
結果が食い違うものがあるが、その非対称は持ち込まない。

**シンボルは識別子であって文字の並びとして扱わない。** `size` や `asUppercase` は
理解しない。必要になったら足す。

#### nil

| セレクタ | 引数 | 返り値 | エラーになる条件 |
| --- | --- | --- | --- |
| `isNil` `notNil` | — | 真偽値 | — |
| `ifNil:` | ブロック | 引数を評価した値、または受け手 | 引数がブロックでなければ `#TypeError` |
| `=` `~=` | 任意 | 真偽値 | **なし** |

**`isNil` と `notNil` はすべての値が理解する。** `nil` かどうかを調べるために
受け手を選ばずに済む必要があるためで、`ifNil:`（§5.2）と同じ理由による。

```smalltalk
nil isNil   "→ true"
1 isNil     "→ false"
```

**`nil` は真偽値ではない**ので、`not` も `&` も理解しない。空セルの値は `nil` なので
（[ADR-0010](adr/0010-empty-cell-value.md)）、**空セルを含む算術がエラーになるのは
この帰結である**（§6.0）。

### 6.3 Array / Range / Interval / Cell

対応するフィクスチャ: [`tests/golden/collections.txt`](../tests/golden/collections.txt)

**並びを持つものが 3 つある。** どれも同じセレクタを理解するが、**要素の正体が違う。**

| クラス | 何の並びか | 要素 | 作り方 |
| --- | --- | --- | --- |
| `Array` | 値の並び | **値** | リテラル配列（§2.4）、`collect:` などの結果 |
| `Range` | セルの矩形 | **`Cell`** | `A1 to: B10`（§4.3） |
| `Interval` | 数の並び | **数** | `1 to: 5`（[ADR-0016](adr/0016-number-interval.md)） |

#### セレクタ

| セレクタ | 引数 | 返り値 | エラーになる条件 |
| --- | --- | --- | --- |
| `size` | — | 整数 | — |
| `isEmpty` | — | 真偽値 | — |
| `first` `last` | — | 要素 | 空なら `#SubscriptOutOfBounds` |
| `at:` | 整数 | 要素 | 整数でなければ `#TypeError`。範囲外なら `#SubscriptOutOfBounds` |
| `sum` | — | 数（空なら `0`） | 数でない値があれば `#TypeError` |
| `count` | — | 整数（空なら `0`） | — |
| `min` `max` `average` | — | 数（空なら `nil`） | 数でない値があれば `#TypeError` |
| `collect:` `select:` `reject:` | 引数 1 つのブロック | **`Array`** | ブロックでなければ `#TypeError` |
| `detect:ifNone:` | 引数 1 つのブロック、引数 0 個のブロック | 要素、または `ifNone:` を評価した値 | 同上 |
| `inject:into:` | 初期値、引数 2 つのブロック | 値 | ブロックでなければ `#TypeError` |
| `sorted:` | 引数 2 つのブロック | **`Array`** | ブロックでなければ `#TypeError` |
| `=` `~=` | 任意 | 真偽値 | **なし** |

**列挙の結果は常に `Array`。** `Range` に `collect:` を送っても `Range` は返らない。
矩形の形を保てないためである。

**ブロックの引数の数が合わなければ `#TypeError`**（§5.1）。

#### 列挙のブロックは真偽値を返さなければならない

`select:` / `reject:` / `detect:ifNone:` / `sorted:` は**ブロックの値を条件として読む。
真偽値でなければ `#TypeError`** である。§7.6 が `whileTrue:` について「受け手が真偽値
以外を返せば `#TypeError`」と定めているのと同じ規則で、**この言語は `false` 以外を真と
みなす経路をどこにも持たない**（§6.2 の `false and: 1` も `#TypeError`）。

```smalltalk
#(1 2 3) select: [:x | x]        "→ #TypeError"
#(3 1 2) sorted: [:a :b | a]     "→ #TypeError"
```

**`Cell` も真偽値ではない。** 委譲（§4.2 の規則 2）は**メッセージの送信に対する規則**で
あって、ブロックの値を条件として読むのは送信ではない。**セルを条件にするには `isTrue` を
送る**（§6.2、[ADR-0022](adr/0022-is-true.md)）。

```smalltalk
"A1 が true、A2 が空、A3 が false のとき"
A1..A3 select: [:c | c]          "→ #TypeError。Cell は真偽値ではない"
A1..A3 select: [:c | c isTrue]   "→ #(true)。空セルは nil なので false"
```

**`isTrue` は `Cell` 自身のセレクタではない**ので、列挙の結果にも同じように送れる
（列挙の結果は常に `Array`）。

```smalltalk
#(true false nil 1) select: [:v | v isTrue]   "→ #(true)"
```

**ブロックの中で生じたエラーはその式全体の値になる**（§6.0）。それ以降の要素は評価しない。

```smalltalk
#(1 2 3) collect: [:x | x / 0]   "→ #DivideByZero"
```

**ブロックを評価しなければ、引数の数も返り値も問われない**（§5.2 と同じ）。
引数の型は評価しなくても見えるので、こちらは常に検査する。

```smalltalk
#() collect: [:a :b | a]         "→ #()。要素が無いので評価しない"
#(1 2 3) collect: [:a :b | a]    "→ #TypeError"
#(1 2 3) collect: 1              "→ #TypeError。引数の型は常に検査する"
```

**「評価しない」は受け手が空の場合に限らない。** `sorted:` の比較は要素が 2 つ以上
なければ起こらないので、**要素が 1 つの `sorted:` は比較のブロックを評価しない。**

```smalltalk
#(1) sorted: [:a :b | a]         "→ #(1)。比べる相手が無いので評価しない"
#(1) sorted: [:a :b | a / 0]     "→ #(1)。同じ理由でエラーも生じない"
#(1 2) sorted: [:a :b | a]       "→ #TypeError。比較が起きるので問われる"
```

#### `sorted:` は安定である

**同順の要素——比較のブロックがどちらの向きにも偽を返す要素——は元の並びを保つ。**
決定性が要件（F-4-4）である以上、**同順の要素の並びも定まっていなければならない。**

```smalltalk
#(1 1.0) sorted: [:a :b | a < b]   "→ #(1 1.0)。整数と小数は値が等しい"
#(1.0 1) sorted: [:a :b | a < b]   "→ #(1.0 1)"
```

#### 集計は `nil` を無視し、列挙は無視しない

**集計は要素を値に解決してから扱う。** `Range` の要素は `Cell` なので、**各 `Cell` の
`value` を見る。** `Cell` そのものは `nil` ではないため、この断りが無いと空セルを
数えてしまう。

**この違いが最も間違えやすい。**

| | `nil` の要素 |
| --- | --- |
| 集計（`sum` `count` `min` `max` `average`） | **値が `nil` なら無視する**（[ADR-0010](adr/0010-empty-cell-value.md)） |
| 列挙（`collect:` など） | **そのまま渡す** |

```smalltalk
"A2 が空のとき"
A1..A3 sum                       "→ 4。空セルを飛ばす"
A1..A3 count                     "→ 2。空セルは数えない"
A1..A3 size                      "→ 3。セルの数なので数える"
A1..A3 collect: [:c | c value]   "→ #(1 nil 3)。飛ばさない"
```

**この規則はクラスを選ばない。** `Range` の空セルだけの話ではなく、`nil` を要素に持つ
`Array` にも同じように当たる。

```smalltalk
#(1 nil 3) sum                   "→ 4"
#(1 nil 3) count                 "→ 2"
#(1 nil 3) size                  "→ 3"
#(1 nil 3) collect: [:x | x]     "→ #(1 nil 3)。列挙は飛ばさない"
```

**`size` と `count` は違う。** `size` は要素の数、`count` は**値が `nil` でない**要素の数
である。`count` は数を要求しないので、文字列が入っていても数える。

列挙で `nil` を飛ばさないのは、**飛ばすと要素数が変わり `select:` と区別が付かなくなる**
ためである。空を除きたければ `select:` を使う。

空の集計で値を返すのは**単位元があるものだけ**である（ADR-0010）。

| セレクタ | 空のときの返り値 |
| --- | --- |
| `sum` `count` | `0` |
| `min` `max` `average` | `nil` |

**`first` / `last` が空のとき `#SubscriptOutOfBounds` になるのは、これらが添字アクセスで
あって集計ではないため。** `first` は `at: 1` と同じ位置付けである。

#### 等価性

**`=` の規則はクラスで分かれる。**

| クラス | 等しいとみなす条件 |
| --- | --- |
| `Array` `Interval` | **同じクラスで、同じ長さで、対応する位置の要素がすべて `=`** |
| `Range` | **正規化した矩形が同じ**（§4.3）。要素の値は見ない |

**クラスが違えば等しくない。** シンボルと文字列の比較（§6.2）と同じ扱いである。
要素どうしの比較は §6.1 の `=` に従うので、整数と小数は値が等しければ等しい。

```smalltalk
#(1 2) = #(1 2)        "→ true"
#(1 2) = #(2 1)        "→ false。順序も見る"
#(1) = #(1.0)          "→ true。要素の比較は値で行う"
#(1 2) = (1 to: 2)     "→ false。クラスが違う"
(1 to: 3) = (1 to: 3.5) "→ true。要素はどちらも 1・2・3"
```

**`Range` だけが要素で比べない。** 範囲は座標の対であって値の入れ物ではないためで
（§4.3）、**値が同じでも別の矩形なら等しくない。**

```smalltalk
"A1 と B1 が 1、A2 と B2 が 2 のとき"
A1..A2 = (B1..B2)   "→ false。値は同じだが矩形が違う"
```

`~=` は `=` の否定である。

#### Array

**要素は値。** リテラル配列（§2.4）と、列挙の結果がこれになる。

```smalltalk
#(1 2 3) collect: [:x | x * 2]   "→ #(2 4 6)。値が渡る"
#(1 2 3) first value             "→ #DoesNotUnderstand。値は value を理解しない"
```

#### Range

**要素は `Cell`**（[ADR-0015](adr/0015-range-enumeration.md)）。ブロックの中でセル自身を
扱えるが、**表記の上では値の配列と見分けが付かない。** §0.3 がセルの表記を
「保持する値の表記に従う」と定めているためである。

```smalltalk
A1..A3 collect: [:c | c]         "→ #(1 2 3)。中身は Cell だが表記は値に従う"
A1..A3 first value               "→ 1。value を送れるかどうかが唯一の見分け方"
A1..A3 collect: [:c | c * 2]     "→ #(2 4 6)。§4.2 の規則 2 が働く"
```

**列挙は行優先。** 左から右へ進み、行が尽きたら次の行へ移る（ADR-0015）。

```smalltalk
"A1=1, B1=2, A2=3, B2=4 のとき"
A1..B2 collect: [:c | c value]   "→ #(1 2 3 4)"
```

**範囲が空になることはない。** セル参照は必ず 1 つ以上のセルを指すため、`isEmpty` は
常に `false` である。`=` は**正規化したうえで同じ矩形かを比べる**（§4.3）。

#### Interval

**要素は数。** `Number to: Number` で作る（ADR-0016）。**刻みは 1。**

**要素は位置から計算し、個数を先に決める。**

| | 定義 |
| --- | --- |
| 個数 | `floor(stop - start) + 1`。負になる場合は `0` |
| `i` 番目の要素 | `start + (i - 1)` |

**個数は `to:` の時点で決まる。** 個数が求まらなければ区間は作れず、`to:` が
`#Overflow` を返す。小数の端では `stop - start` そのものが倍精度に収まらないことが
あり、[ADR-0013](adr/0013-non-finite-numbers.md) の規則がそのまま当たる。
**整数の端は任意精度なので、どれだけ離れていても区間を作れる。**

```smalltalk
(-1.0e308 to: 1.0e308)   "→ #Overflow。差が倍精度に収まらない"
(0.0 to: 1.0e308)        "→ 作れる。差は収まる"
(1 to: 1e400)            "→ 作れる。整数の端は任意精度"
```

**足し込みで進める読み方は採らない。** 小数は倍精度なので（§6.1）、`1e21` 付近では
**1 を足しても値が変わらず**、上端に到達しないまま列挙が終わらなくなる。個数を先に
決めれば、そうした端点でも有限で決定的である。

```smalltalk
(1.5 to: 4) size          "→ 3。要素は 1.5・2.5・3.5"
(1 to: 0.5) size          "→ 0。個数の式が負になるので 0"
(1.0e21 to: 1.0e21) size  "→ 1。1 を足しても値が変わらない大きさでも止まる"
```

個数が極端に大きい区間を列挙した場合の打ち切りは、本書ではなく要件 N-5 が定める。

```smalltalk
1 to: 5              "→ 1 to: 5。表記は正準形と同じ"
(1 to: 5) sum        "→ 15"
(1 to: 3.5) last     "→ 3。刻みが 1 なので 3 で止まる"
```

**逆向きは空になる。`Range` が正規化するのとは逆の扱いである**（ADR-0016）。

| | 逆向きに書いたとき |
| --- | --- |
| `Range` | **正規化する。** `B10 to: A1` は `A1 to: B10` と同じ矩形（§4.3） |
| `Interval` | **空になる。** `5 to: 1` は要素を持たない |

```smalltalk
(5 to: 1) size       "→ 0"
(5 to: 1) isEmpty    "→ true"
(5 to: 1) first      "→ #SubscriptOutOfBounds"
```

範囲を正規化するのはドラッグの向きで結果が変わらないようにするためだが、数の区間で
`5 to: 1` を読み替えると**繰り返しの回数が意図せず増える**。`1 to: n` が `n` が 0 のとき
空になることは、むしろ期待される挙動である。

#### Cell

**`Cell` 自身が理解するのは `value` と `to:` だけ**（§4.2、§4.3）。それ以外は保持する値へ
委譲する。

| セレクタ | 引数 | 返り値 | エラーになる条件 |
| --- | --- | --- | --- |
| `value` | — | 保持する値（空なら `nil`） | — |
| `to:` | `Cell` | `Range` | 引数が `Cell` でなければ `#TypeError` |

```smalltalk
A1 value    "→ 1。Cell 自身が理解する"
A1 size     "→ 3。A1 が 'abc' なら、値へ委譲する"
A1 to: 5    "→ #TypeError。範囲はセルの対からしか作れない"
```

**空になりうるのは `String`（§6.2）と `Array` と `Interval`** である。`Range` は空に
ならない。これが §5.2 の `ifEmpty:` の受け手になれる型の一覧である。

### 6.4 本節で定めないもの

| 対象 | 扱い |
| --- | --- |
| `do:` | **§7.6 で定めた。** セレクタの理解は文脈に依らないので数式からも送れるが、**数式は副作用を持てない**（F-2-10）ため受け手が返るだけで何も観測できない |
| `to:by:`（刻みの指定） | 将来。`Interval` の刻みは 1 に固定した（ADR-0016） |
| `Array` の連結 `,` と `asArray` | 将来。必要になったら足す |
| `Date` / `Time` | 将来。要件 F-2-7 は `Date` を挙げているが、日付・時刻演算は F-2-12（優先度 S）であり、決定性（F-4-4）のため「現在時刻」を明示 API 経由にする設計が別途要る。M0 の範囲から外す |
| `Sheet` | 将来。要件 F-2-7 が挙げているが、数式から触れると副作用の経路ができる（F-2-10）。§7.9 のとおり M4 で扱う |
| Excel 互換の別名関数（`SUM(...)`） | 将来（要件 F-2-14、優先度 L） |
| ユーザー定義関数 | MVP 対象外（未決論点 D-9） |
| エラーの捕捉（`ifError:`） | 未決論点 D-8 |

## 7. マクロ

対応するフィクスチャ: [`tests/golden/macros.txt`](../tests/golden/macros.txt)、
[`tests/golden/assignment.txt`](../tests/golden/assignment.txt)

**マクロは副作用を持てる。** §1〜6 が定めたのは数式であり、数式は副作用を持てない
（要件 F-2-10）。本節はその外側を定め、**数式とマクロの境界を文法の側から引く。**

### 7.1 開始記号

**同じ字句・同じ式・同じセレクタを、違う開始記号から読む。**

```ebnf
(* 開始記号は 3 つ。数式が 1 つ、マクロが 2 つ *)
formula          = expression ;                     (* §3.1。セルの内容が "=" で始まるもの *)
macro definition = macro pattern , macro body ;     (* ブックに保存する形（要件 F-3-1） *)
macro body       = [ temporaries ] , statements ;   (* その場で実行する形 *)
```

| 開始記号 | どこから入るか |
| --- | --- |
| `formula` | セルに `=` で始まる内容を入れたとき（要件 F-2-1） |
| `macro definition` | マクロエディタでブックに保存するとき（要件 F-3-1） |
| `macro body` | 名前を付けずにその場で実行するとき（CLI・MCP の試し実行、要件 F-6） |

**ゴールデンテストは `macro body` を使う**（ケースの先頭の `!macro`、
[ADR-0018](adr/0018-golden-macro-directive.md)）。受け入れ基準の 3 番目が挙げている例も
この形である。**宣言部を持つ定義は、`!macro` に起動するメッセージを添えて固定する**
（`!macro from: 1 to: 3`）。これはフィクスチャが「どのメッセージでマクロを始めるか」を
言うだけで、**呼び出しの構文を言語に足すものではない。** 実際の起動も UI や MCP が
同じことをする（要件 F-3-8）。

#### 違うのは構文だけで、語彙は同じ

**セレクタの理解は文脈に依存しない。** `do:`（§7.6）は本節で定めるが、数式から送っても
構文エラーにはならない。数式は副作用を書けないので、受け手が返るだけで何も観測できない
（§6.4）。**「数式では理解しないセレクタ」という区別を作らない。** クラスごとのセレクタ表を
文脈の数だけ持つことになり、説明も実装も倍になるためである。

#### マクロの宣言

```ebnf
macro pattern = unary selector
              | keyword , identifier , { keyword , identifier } ;
```

```smalltalk
monthlyTotal
    | total |
    total := (B2 to: B13) sum.
    B14 := total.
    ^ total

summarize: label
    | total |
    total := (B2 to: B13) sum.
    A14 := label.
    B14 := total
```

- 名前は**単項セレクタかキーワードパターン**（§1.4）。**二項セレクタは認めない。**
  マクロの名前に記号を使う理由が無く、`+` のような名前は読み手を混乱させる。
- 引数はキーワードの数だけ取る。引数は本体の中で識別子として読めるが、
  **引数への代入は `#Syntax`**（一時変数を宣言して写す）。
- **宣言されたマクロを呼び出す構文は本書では定めない**（§7.9）。

### 7.2 マクロの本体

```ebnf
macro body  = [ temporaries ] , statements ;
temporaries = "|" , { identifier } , "|" ;
statements  = { statement , "." } , ( statement | return ) , [ "." ] ;
statement   = assignment | expression ;
return      = "^" , expression ;
```

```smalltalk
| a |
a := 3.
^ a + 1     "→ 4"
```

#### 一時変数

- **宣言は本体の先頭にだけ置ける。** 2 つに分けることも、文の後ろに置くこともできない。
- **同じ名前を二重に宣言できない。**
- **宣言しただけの一時変数は `nil`。**
- 名前を 1 つも書かない `| |` も認める。

```smalltalk
| a b |         "2 つ宣言する"
| |             "何も宣言しない。書いても良いが意味は無い"
| a a |         "→ #Syntax。二重の宣言"
```

#### 文の列

- 文は `.` で区切る。**末尾の `.` は書いてよい。**
- **文が空になる区切りは書けない**（`1. . 2` は `#Syntax`）。
- **本体には文が 1 つ以上要る。** 宣言だけの本体は `#Syntax` とする。
  §5.1 が `[]` を `#Syntax` としたのと同じ扱いである。

#### 返却

- **`^` は文の列の最後の文としてだけ書ける。** 後ろに文を続けられない。
  到達しない文を書ける形にしても、読み手が得をしない。
- **`^` が無ければマクロは `nil` を返す。** マクロは値を返すために書くとは限らず、
  セルを書き換えて終わるものが多い。
- 早く抜けたい場合はブロックの中の `^` を使う（§7.5 の非局所リターン）。

#### エラーで終わる

**文の値がエラーなら、その文の列はそこで打ち切られ、そのエラーが列の値になる**
（[ADR-0027](adr/0027-macro-execution.md)）。マクロ本体では**マクロがそのエラーで終わり**、
書き込みは巻き戻る（§7.8）。

```smalltalk
1 / 0.
^ 3          "→ #DivideByZero。値を捨てる文でも止まる"

| a |
a := 1 / 0.
^ 3          "→ #DivideByZero。一時変数への代入でも同じ"
```

**エラーを黙って捨てる経路を作らない。** 値を捨てる文でエラーを見過ごせると、
途中で失敗したマクロが成功したように見える。§3.6 の「最初に生じたエラーを返す」を
文の列にも当てたものである。

### 7.3 代入

```ebnf
assignment        = assignment target , ":=" , expression ;
assignment target = identifier | cell reference ;
```

#### 代入は文であって式ではない

**式の中に代入は現れない。**

```smalltalk
3 + (a := 1)       "→ #Syntax"
3 max: (a := 5)    "→ #Syntax"
a := b := 3        "→ #Syntax。連鎖代入も書けない"
```

Smalltalk-80 は代入を式として扱うが、ここでは文とした。**数式が拒否する範囲が構文の
1 箇所で決まる**ためである。式の中に代入が現れうると、`ifTrue:` の引数やブロックの本体に
代入が紛れ込む経路を、開始記号ごとに別々の規則で塞ぐことになる。

**代入は値を持たない。** ブロックの最後の文が代入なら、そのブロックの値は `nil`（§7.5）。

#### 左辺

- **宣言の無い識別子への代入は `#Syntax`。** 宣言の書き忘れを静的に捕まえる。
- 識別子を**読む**方は §4.2 のまま `#Ref` である。名前付き範囲（要件 F-1-8）が入れば
  同じ構文が解決できるようになるが、**代入の左辺は解決できるようにならない。**
- 左辺になれるのは**宣言済みの一時変数とセル参照だけ。** `3 := 1` も `A1:B2 := 0` も
  `#Syntax` である（範囲への代入は §7.9）。
- **マクロの引数（§7.1）とブロックの引数は左辺になれない。** 書き換えたければ一時変数を
  宣言して写す。Smalltalk-80 と同じ扱いである。

### 7.4 セルへの代入

**`B14 := total`**（[ADR-0007](adr/0007-range-cell-reference-assignment.md) D-3）。
表計算のマクロで最も多い操作なので、短く読める形を採っている。

```smalltalk
| total |
total := (B2 to: B13) sum.
B14 := total.
B15 := total / 12
```

- **左辺のセル参照は読まれない。** 書き込み先を指すだけなので、元の値がエラーでも通る。
  `A1 := A1 + 1` の右側の `A1` だけが読まれる。
- **書き込まれるのは値であって数式ではない。** 書き込み先に数式が入っていたら、
  その数式は値で置き換わる。Excel でセルに値を入力したときと同じで、
  以後そのセルは参照を追わない。
- **書き込んだ値は同じマクロの中で読み直せる。**
- **右辺がエラーならセルは書き換わらず、マクロはそのエラーで終わる**（要件 F-3-4）。
  エラーを値としてセルに残す経路は作らない。数式の側でエラーが値として伝播すること
  （§3.7）との違いである。§7.2 の「エラーで終わる」の 1 つの場合でもある。
- **書き込みは同じマクロの中で下流の数式に届く**（ADR-0027）。`B1` が `=A1 + 1` なら、
  `A1 := 5. ^ B1` は `6`。途中のどの時点で読んでも、その時点の内容で全体を計算し直した
  値と同じになる。いつ計算するかは実装の問題で、言語からは見えない。

#### 書き込んだ値の置き方

**値は §0.3 の表記で内容として置き、§4.4 の読み方で同じ値に戻る**（ADR-0027）。
セルは内容（原文）を持つもので、値を直接は持たない。

| 右辺の値 | 置かれる内容 |
| --- | --- |
| 数・真偽値・シンボル | §0.3 の表記。小数は同じ値に戻る |
| 文字列 | **常に引用符付き。** `'3'` は数に、`'=B1'` は数式にならない |
| 配列 | §0.3 の表記。**要素にエラーがあれば、そのエラーでマクロが終わる** |
| `nil` | **セルを空にする**（ADR-0010） |
| `Cell` | そのセルの値（§4.2）。書いた後は元のセルを追わない |
| ブロック・範囲・区間 | **`#TypeError`。** リテラルで書けない |

```smalltalk
A1 := '3'.            "A1 の値は文字列 '3'"
A1 := #(1 1.0e400).   "→ #Overflow。#(#Overflow) はシンボルの配列として読み戻されてしまう"
A1 := 1 to: 3.        "→ #TypeError"
```

### 7.5 マクロのブロックと非局所リターン

```ebnf
macro block = "[" , [ block arguments ] , [ temporaries ] , statements , "]" ;
```

**マクロに現れるブロックは、本体に文の列と一時変数を持てる**（要件 F-2-5）。
数式のブロック（§5.1）が式ちょうど 1 つだったのは、代入が書けない以上は文を並べる意味が
無かったためで、マクロではその前提が外れる。

```smalltalk
[:x | | t | t := x * 2. t + 1] value: 3   "→ 7"
[1. 2. 3] value                           "→ 3。ブロックの値は最後の文の値"
```

**外側の一時変数への代入も文なので、値を持たない。**

```smalltalk
| a |
^ [a := 1] value    "→ nil。a は外側で宣言してある（§7.3）"
```

- **ブロックの値は最後の文の値。** 最後が代入なら `nil`。
- **途中の文の値がエラーなら、そこで打ち切られてそのエラーがブロックの値になる**（§7.2）。
  `[1 / 0. 2] value` は `#DivideByZero`。
- **ブロックは外側の一時変数を読み書きできる。**
- **外側と同じ名前を内側で宣言できない。** ブロック引数と同じ名前の一時変数も同じ。
  影になった名前は読み手が追えないため、`#Syntax` とする。
  **数式のブロックにも同じ規則が当たる**（§5.1）。一時変数を持てない分、数式に現れるのは
  引数どうしの重なりだけになる。

#### 非局所リターン

**ブロックの中の `^` はマクロ全体を終える。**

```smalltalk
#(1 2 3) do: [:e | e > 1 ifTrue: [^ e]].
^ 0
   "→ 2。ブロックの中の ^ でマクロが終わる"
```

`^` に達しなければそのまま次の文へ進む。**ブロックの中でも `^` は文の列の最後の文**であり、
`[^ 1. 2]` は `#Syntax` である（§7.2 と同じ規則）。

繰り返しの途中で抜ける手段はこれだけになる。`do:` に途中で止める仕組みを足すより、
Smalltalk-80 と同じ形を 1 つ持つ方が覚えることが少ない。

### 7.6 繰り返し

**§5.3 と §6.4 がここへ送っていた 2 つを定める。**

| セレクタ | 受け手 | 引数 | 返すもの |
| --- | --- | --- | --- |
| `do:` | `Array` / `Range` / `Interval` | 引数 1 つのブロック | **受け手** |
| `whileTrue:` | 引数を取らないブロック | 引数を取らないブロック | `nil` |

```smalltalk
| sum |
sum := 0.
#(1 2 3) do: [:e | sum := sum + e].
^ sum                                  "→ 6"

| i |
i := 0.
[i < 3] whileTrue: [i := i + 1].
^ i                                    "→ 3"
```

- **`do:` は受け手を返す。** 値を集めるのは `collect:`（§6.3）である。
  ただし**ブロックの値がエラーなら、そのエラーが `do:` の値になる**（`collect:` と同じ、§6.0）。
- **範囲の列挙は `Cell` を渡す**（[ADR-0015](adr/0015-range-enumeration.md)）。順は行優先。
  区間（§6.3）は数を渡す。
- ブロックの引数の数が合わなければ `#TypeError`（§5.1 の `value` の規則と同じ）。
- **`whileTrue:` は受け手を評価して `true` の間、引数を評価する。**
  受け手が真偽値以外を返せば `#TypeError`。引数がブロックでなければ `#TypeError`
  （§5.2 の条件式と同じ理由で、値を渡せると先行評価になる）。
  受け手がブロックでなければ `#DoesNotUnderstand`。
- **どちらも数式から送れる**（§7.1）。ただし数式では何も観測できない。
- **数式でも停止しない繰り返しは書ける。** 代入が書けなくても `[true] whileTrue: [1]` は
  書けるため、**上限は数式にも当たる**（§7.8）。

### 7.7 数式とマクロの境界

| 構文 | 数式 | マクロ |
| --- | --- | --- |
| 式の評価 | 可 | 可 |
| 一時変数の宣言 `\| a b \|` | **`#Syntax`** | 可 |
| 代入 `a := 3` | **`#Syntax`** | 可 |
| セルへの代入 `B14 := total` | **`#Syntax`** | 可 |
| 文の列 `.` | **`#Syntax`** | 可 |
| `^` による返却 | **`#Syntax`** | 可 |
| ブロックの本体 | 式ちょうど 1 つ | 文の列と一時変数 |
| ブロックの中の `^` | **`#Syntax`** | 非局所リターン |
| セレクタ（`do:` を含む） | すべて送れる | すべて送れる |
| カスケード `;` | 無い | 無い |

**セルに入れた数式の中でも同じ。** `=B1 := 3` は `#Syntax` であり、
**数式からセルを書き換える経路は存在しない**（要件 F-2-10）。

### 7.8 実行時の制約

**本書は文法と意味論を定める。実装は M4 に属する**が、言語の側から見える帰結だけを書く。

| 要件 | 制約 | 言語から見えるもの |
| --- | --- | --- |
| F-3-4 | 1 回の実行が単一のトランザクション。失敗したら開始前に巻き戻る | エラーで終わったマクロの書き込みは残らない |
| F-3-5 / N-5 | ステップ数・時間・再帰深度に上限 | 超過した**評価**は中断して **`#Timeout`**。時間はホストが掛ける（下記） |
| F-3-6 | ネットワーク・ファイルシステム・DOM に触れない | そのためのセレクタを持たない |

#### 上限は数式にも当たる

**要件 N-5 と F-3-5 はマクロについて書いているが、上限は開始記号で変えない。**
`whileTrue:`（§7.6）は数式からも送れるため、**数式にも停止しない経路がある。**
代入が書けないことは止まる保証にならない。

```smalltalk
"マクロ"
| i |
i := 0.
[true] whileTrue: [i := i + 1].
^ i                                "→ #Timeout"

"数式。同じ上限が当たる"
[true] whileTrue: [1]              "→ #Timeout"
```

**これは要件の変更ではなく適用範囲の明示である。** N-5 が禁じているのは
「ブラウザをフリーズさせること」であり、数式に上限を掛けないとその目的を満たせない。

上限の具体的な値は本書では定めない。**環境によって妥当な値が違う**ためで、
要件 N-1〜N-3 の性能目標と併せて M4 で決める。

#### 時間の上限は言語の外で掛ける

**評価器が数えるのはステップ数と再帰深度だけである**（ADR-0027）。時間で打ち切ると
同じ原文の結果がマシンの速度で変わり、決定性（要件 F-4-4）を満たさない。
時間の上限は評価器を動かす側（Web UI・MCP サーバー・CLI）が掛ける。
**超えた実行は打ち切られて `#Timeout` になり、書き込みは何も残らない**（§7.8 の表と同じ帰結）。

**再帰深度の上限はマクロで初めて意味を持つ。** ブロックは一時変数を通して自分を呼べる。

```smalltalk
| f |
f := [:n | f value: n + 1].
^ f value: 1                       "→ #Timeout"
```

## 付録 A. 本書で確定させた判断

§1〜7 を書く過程で、次の判断を**この文書の中で確定させた。** 覆すなら ADR を書く。

| 論点 | 決定 | 根拠 |
| --- | --- | --- |
| 指数の `e` の大文字 | 認めない | `1E3` の `E3` がセル参照と衝突する（ADR-0007 D-2） |
| `5.` の扱い | 小数として認めない | §7 の文区切り `.` と紛れる |
| 先頭の 0 | 認める（`007` は `7`） | 桁を揃えて書けると都合が良い |
| 負のリテラルと二項の `-` | 直前のトークンで決める（§2.1） | 空白の有無で意味が変わる方式より事故が少ない |
| 範囲トークンと一次式の終端 | 終端に含める（§2.1） | 範囲は §3.1 の `primary` であり、`)` や `]` と同じ位置に立つ |
| `#A1` の綴り | シンボルとして受理する（§2.3） | `#` の後ろは綴り。`#A1` と `#'A1'` が同じシンボルになる |
| 空白の無い `a:=1` | 代入として切り出す（§1.4） | 最長一致より代入を優先する。空白の有無で意味を変えない |
| 二項セレクタの長さ | 1〜2 文字 | Smalltalk-80 の慣習 |
| リテラル配列の裸の識別子 | シンボルになる | Smalltalk の慣習。ペルソナ P1 の期待に合う |
| リテラル配列の裸のキーワード | 隣り合う間だけ 1 つのシンボル（§2.4） | Smalltalk の慣習（走査が文字を追う）。`#(12)` と `#(1 2)` の区別と同じ性質 |
| エラーの期待値の表記 | 種別シンボルのみ | 文言の変更でゴールデンテストが落ちるのを避ける |
| 構文エラーの位置と説明文 | 値には載せず、値と組にして返す（§3.8） | 載せると同じ種別でも位置が違えば別の値かを決めることになる。§6.0 は定めていない |
| `A1 = A2` の意味 | 値の比較（`Cell` は `=` を定義しない） | 委譲の規則（ADR-0008）をそのまま適用する。Excel の `=A1=A2` と同じ |
| 引数に現れたセル | 転送の際に値へ解決する（§4.2） | 委譲は受け手の側でしか起きず、これが無いと `A1 + B1` が値どうしの演算にならない |
| 受け手のセルを解決する時期 | 引数を評価するより前（§4.2） | §6.0 の「受け手が先」を順序として読む。`A1 + (1 / 0)` は A1 の値が先に決まる |
| 循環参照の位置付け | 参照ではなくセルの値（§4.2） | 参照そのもののエラーにすると、範囲を作るだけで両端を読むことになる（ADR-0023） |
| 範囲の表記 | 正準形と同じ `A1 to: B10` | 糖衣の設定（`range.delimiter`）で読み方が揺れない |
| 逆向きの範囲 | 正規化して同じ矩形 | ドラッグの向きで結果が変わらない方が期待に沿う |
| 糖衣の文法上の位置 | 字句規則（1 つの範囲トークン） | 構文規則として書くと、空白を読み飛ばす実装が `A1 .. B10` を受理してしまう |
| 裸の識別子 | 評価時に `#Ref` | 名前付き範囲が入れば同じ構文が解決できるようになる |
| `A0`（行 0） | `#Ref` | 行は 1 始まり（F-1-3）。形は正しいが存在しない |
| 先頭に空白のある `=`（`  =A1 + 1`） | 数式にしない（§4.4） | 数式かどうかが原文の見た目どおりに決まる。打ち間違えた空白が黙って数式を殺さない |
| 空白だけの内容 | 文字列（§4.4） | 空セルは原文が空文字列のときだけ。段 2 が空白を無視するのは字句の規則であって、空かどうかの判定ではない |
| 数式のブロックの本体 | 式ちょうど 1 つ | 数式は副作用を持てず（F-2-10）、代入が書けない以上は文を並べる意味が無い |
| 条件式の引数 | ブロック以外は `#TypeError` | 値を渡せると先行評価になり、F-2-9 を満たさない |
| 引数の数の検査の適用範囲 | ブロックを評価する経路すべてに当てる（`true ifTrue: [:x \| x]` は `#TypeError`） | §5.1 の規則を `value:` の送信に限ると、同じブロックが送り方で別の意味を持つ |
| 選ばれなかった側の引数の数 | 検査しない（`false ifTrue: [:x \| x]` は `nil`） | 型は引数そのものの性質だが、引数の数は評価するときに初めて問題になる |
| ブロックの表記 | `aBlock` | 本体の原文だと空白の入れ方でゴールデンテストが落ちる |
| 非有限値（`Infinity` `NaN`） | 値として持たない。`#Overflow` にする | `rounded` / `truncated` が常に整数を返す規則を保つため（ADR-0013） |
| `min:` / `max:` の同値 | 引数を返す（`1 min: 1.0` は `1.0`） | `<` `>` による定義から導ける。但し書きを増やさない |
| 負のゼロ | 値としては残し、表記は `0.0` | ゴールデンテストが符号の違いだけで落ちるのを避ける |
| アンダーフロー | `0.0` に丸める。エラーにしない | 下側には丸め先があり、上側には無い。「精度が落ちる」側に当たる |
| 文字型 | 持たない | F-2-7 の組み込みクラスに無い。`indexOf:` は部分文字列を取る |
| `indexOf:` が見つからないとき | `0` | 添字が 1 起点なので「ありえない位置」として機能する（Smalltalk-80） |
| `asNumber` が読めないとき | `nil`。エラーにしない | 既定値を `ifNil:` で与えられる。変換の失敗は誤りではない |
| `asNumber` が受理する形 | §2.1 の数値リテラルちょうど | 新しい規則を作らない。リテラルと文字列で受理する形が常に一致する |
| `asNumber` が倍精度に収まらないとき | `#Overflow`。`nil` にしない | 形は §2.1 に合っており、読めなかったのではない。再利用するのは形だけでなく値の作り方も含む（ADR-0013） |
| シンボルと文字列の比較 | 両向きとも `false` | 別のクラス。Smalltalk の実装にある非対称は持ち込まない |
| シンボルの `size` | 理解しない | 識別子であって文字の並びとして扱わない。必要になったら足す |
| 範囲の列挙順 | 行優先 | 読み順であり、Excel の配列数式とも揃う（ADR-0015） |
| `first` / `last` が空のとき | `#SubscriptOutOfBounds` | 添字アクセスであって集計ではない。`at: 1` と同じ位置付け |
| `at:` を入れるか | 入れる | Issue #5 の一覧には無いが、要素を取る手段が他に無い。ADR-0014 が想定済み |
| `size` と `count` の違い | `size` は要素の数、`count` は `nil` でない要素の数 | 集計だけが `nil` を無視するという規則の帰結 |
| 列挙の返り値 | 常に `Array` | `Range` に `collect:` を送っても矩形の形は保てない |
| `Array` / `Interval` の `=` | 同じクラス・同じ長さ・対応する要素がすべて `=` | 並びとしての内容が同じなら等しい。クラス違いは `false`（§6.2 と同じ扱い） |
| 列挙のブロックの返り値 | 真偽値以外は `#TypeError`（§6.3） | §7.6 の `whileTrue:` と同じ規則。`false` 以外を真とみなす経路をどこにも持たない |
| ブロックが `Cell` を返したとき | 条件として読めない（`#TypeError`）。§6.3 | 委譲は送信に対する規則であって、ブロックの値を条件として読むのは送信ではない |
| `isTrue` の置き場 | すべての値が理解する（§6.2、ADR-0022） | `Cell` 自身に足すと §4.2 の規則 1 の一覧が増え、列挙の結果（`Array`）には使えなくなる |
| `sorted:` の同順 | 安定（元の並びを保つ） | 決定性（F-4-4）が要件である以上、同順の要素の並びも定まっていなければならない |
| `Range` の `=` | 正規化した矩形が同じ。要素の値は見ない | 座標の対であって値の入れ物ではない（§4.3） |
| 負の数の `sqrt` | `#Overflow` | 数の範囲・定義域の誤りとして 1 つの種別にまとめた（ADR-0013） |
| `rounded` の半整数 | 大きい側へ（`2.5 rounded` は `3`） | Smalltalk-80 の `rounded` に合わせる |
| `between:and:` の逆向き | `false`（正規化しない） | 範囲（§4.3）と違い、区間は向きに意味がある |
| `=` `~=` の型違い | エラーにせず `false` / `true` | `nil` や文字列と突き合わせる場面が普通にある |
| `Date` / `Sheet` を §6 に入れるか | 入れない | F-2-7 は挙げているが、日付は F-2-12（優先度 S）で決定性の設計が別途要り、`Sheet` は数式から触れると副作用の経路になる（F-2-10） |
| マクロの開始記号 | 宣言付きと本体だけの 2 つを持つ | ブックに保存する経路（F-3-1）と、その場で試す経路（受け入れ基準 3、F-6）の両方が要る |
| セレクタの文脈依存 | 持たせない。数式とマクロの違いは構文だけ | クラスごとのセレクタ表を文脈の数だけ持つことになり、説明も実装も倍になる |
| 代入 | 式ではなく**文**とする | 数式が拒否する範囲が構文の 1 箇所で決まる。Smalltalk-80 とは違う |
| 連鎖代入 `a := b := 3` | `#Syntax` | 代入を文にしたことの帰結 |
| 宣言の無い識別子への代入 | `#Syntax` | 宣言の書き忘れを静的に捕まえる。読む方は §4.2 のまま `#Ref` |
| `^` の位置 | 文の列の最後の文だけ | 到達しない文を書ける形にしても読み手が得をしない |
| `^` の無いマクロ | `nil` を返す | セルを書き換えて終わるマクロが多く、値を返すとは限らない |
| ブロックの中の `^` | 非局所リターン（マクロ全体を終える） | 繰り返しから抜ける手段を 1 つにする。Smalltalk-80 と同じ |
| ブロックの値 | 最後の文の値。代入なら `nil` | 代入が値を持たないことの帰結 |
| 名前の影 | 外側と同じ名前を内側で宣言するのは `#Syntax` | 影になった名前は読み手が追えない |
| 名前の影と二重宣言の適用範囲 | 数式のブロック引数にも当てる | 根拠が開始記号で変わらない。検査も構文解析器の 1 箇所で済む |
| マクロの名前 | 単項セレクタかキーワードパターン。二項は認めない | 記号の名前を付ける理由が無く、読み手を混乱させる |
| 引数への代入 | `#Syntax` | 一時変数を宣言して写す。Smalltalk-80 と同じ |
| カスケード `;` | 入れない。§1.6 のトークンからも外す | 受け手を共有する副作用の列が要る場面が無い |
| `do:` の返り値 | 受け手 | 値を集めるのは `collect:`（§6.3）。役割を分ける |
| `whileTrue:` の返り値 | `nil` | 値を作るための繰り返しではない |
| セルへの代入の右辺がエラー | 書き込まず、マクロはそのエラーで終わる | F-3-4 の巻き戻しと揃える。エラーを値としてセルに残さない |
| 文の値がエラー | その文の列を打ち切り、エラーを列の値にする。マクロ本体ならマクロが終わる | エラーを黙って捨てる経路を作らない（ADR-0027） |
| 書き込みと下流の数式 | 同じマクロの中で届く | 途中で読んだ値が内容と食い違わない（ADR-0027） |
| 書き込んだ値の置き方 | §0.3 の表記で内容にする。文字列は引用符付き、`nil` は空。書けない値は `#TypeError` | セルが内容だけを持つ形を崩さない。保存（F-5-1）もそのまま（ADR-0027） |
| 時間の上限 | 評価器の外（ホスト）で掛ける | 評価器の結果を決定的に保つ（F-4-4、ADR-0027） |
| 上限の超過 | `#Timeout` | F-8-2 の種別で足りる。種別を増やさない |
| 上限の適用範囲 | 数式にも当てる | `whileTrue:` は数式からも送れ、停止しない経路がある。要件 N-5 の目的（フリーズさせない）は開始記号で変わらない |
| 宣言部のゴールデンテスト | `!macro` に起動するメッセージを添える | 呼び出しの構文を言語に足さずに、宣言部の受理・拒否を固定できる |

## 付録 B. 本書の外へ持ち越した論点

**§7 で閉じた 2 件**（カスケード `;` は入れない、`whileTrue:` は入れる）**を落とし、
残りは次のとおり。** 本書は §7 で終わるため、行き先はマイルストーンになる。

- **セルの同一性を比べる手段** — §4.2 は `=` を値の比較と定めた。
  同一性が必要になったら専用のセレクタを足す。数式で必要になる場面が無いため保留
- **文字列と Unicode** — 決めるのは 2 つ。**(1)** `size` と添字が何を 1 と数えるか
  （コードポイントか書記素クラスタか）、**(2)** `asUppercase` / `asLowercase` が
  ASCII 外の文字をどう写すか。**非 ASCII のリテラルを扱えること自体は未決ではない。**
  §1.1 がソースを Unicode のテキストと定めており、保持・比較・連結は上の 2 点に
  依存しない（`tests/golden/strings.txt` の「非 ASCII」の節で固定してある）。
  **UI（`packages/web`）が実際に扱う文字を見てから決める方が確実**なので、M0 では決めない。
  **未決のまま。** ただし評価器は実装として何かを選ばざるを得ないため、M2 の段階 4 で
  **暫定的に「コードポイントで数え、写し方はロケールに依存しない Unicode の既定に従う」**を
  採った（[#32](https://github.com/kittenkiki15/sec/issues/32)）。**決めるのは UI を見てからで、この暫定には縛られない**
- **範囲への代入** — §7.9。要件 F-3-3 が挙げているが、配列を代入したときの展開が
  未決論点 D-4（スピル）と絡む。**D-4 の結論より先に単一値だけ決めると食い違う恐れがある**
- **マクロから他のマクロを呼び出す構文** — §7.9。要件 F-3-7（優先度 S）。再帰深度の上限
  （要件 N-5）と併せて M4 で決める
