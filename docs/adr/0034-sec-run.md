# ADR-0034: `sec run` はシートを仮の JSON で受け渡し、時間の上限は既定 5 秒

- 状態: accepted
- 日付: 2026-09-24
- 関連: 要件 F-3-5・F-5-1・N-5、仕様書 §7.1・§7.8、開発方針「フィードバックループは CLI で回す」、
  [ADR-0009](0009-golden-sheet-directives.md)、[ADR-0018](0018-golden-macro-directive.md)、
  [ADR-0027](0027-macro-execution.md)、[#80](https://github.com/kittenkiki15/sec/issues/80)

## 背景

M4 の段階 8 で、マクロを CLI から実行する `sec run` を作る。ADR-0027 は**時間の上限を
`sec run` も掛ける**と決めたが、次の 4 点は決まっていなかった。

1. **マクロが読み書きするシートの初期状態をどう与えるか。** 開発方針の例は
   `sec run book.secbook macro.st` だが、`.secbook` の形式（要件 F-5-1）は M7 で決める。
2. **何を出力するか。** マクロの主な効果はセルへの書き込みで、値だけでは何をしたかが見えない。
3. **時間の上限の既定値と、変えられるか。**
4. **マクロの原文と、宣言部を持つ定義を起動するメッセージをどう与えるか。** 起動の構文は言語に無い（§7.1）。

## 選択肢

### 1. シートの初期状態

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A | `--cell 'A1 := 3'` を繰り返す | ゴールデンテストのセルの指定（ADR-0009）と同じ区切り。M7 の形式と衝突しない | 実行後のシートを同じ形で出せない |
| B | **仮の JSON ファイル** | 実行後のシートを同じ形で書き出し、次の実行にそのまま渡せる | M7 の形式を先取りし、後で食い違う恐れ |
| C | 空のシートだけ | 決めることが無い | 読むマクロを試せない |

### 2. 出力

| 案 | 内容 |
| --- | --- |
| D | stdout は値だけ（`sec eval` と同じ） |
| E | **stdout に値と確定した書き込み。** さらに `--out` の JSON に実行後の空でない全セル |
| F | 値と、`--show A1..B3` で指定したセルの値 |

### 3. 時間の上限

| 案 | 内容 |
| --- | --- |
| G | **既定 5 秒、`--timeout <ms>` で変えられる** |
| H | 既定 1 秒、変えられる。遅い CI では誤って当たる恐れがある |
| I | 5 秒で固定 |

### 4. マクロと起動するメッセージ

| 案 | 内容 |
| --- | --- |
| J | **原文はファイルで受け、起動するメッセージは `--send 'from: 1 to: 3'`** |
| K | 原文を引数で受ける。複数行のマクロをシェルで書きにくい |

## 決定

**利用者の選択で B・E・G・J を採る。**

```
sec run <マクロ> [--sheet <JSON>] [--out <JSON>] [--send <送信>] [--timeout <ms>]
```

- **シートの JSON は番地から内容の原文への対応**（`{"A1": "3", "B1": "=A1 * 2"}`）。
  **値は持たない**——値は原文から導かれる（`Sheet` と同じ向き）。
  - 内容は文字列に限る。数を受けると `3` と `'3'` のどちらのつもりかが曖昧になる（ADR-0021）
  - 番地は正規化する（ADR-0020）。**正規化して同じセルになる綴りが 2 つあれば拒む**
  - 内容が空文字列のセルは空のセルとして読み飛ばす（ADR-0010）
  - 書くときは**行を先に、列を後に並べる。** 置いた順のままだと、マクロが書き込んだ順が差分に出る
  - **`.secbook` ではない。** M7 で形式を決めたら、`sec run` もそちらを読むように見直す
- **stdout は値と確定した書き込み。** 書き込みは行の順に `B1 := 6` の形で、ゴールデンテストの
  セルの指定（ADR-0009）と同じ区切り。空にしたセルは `A1 :=`（末尾の空白は見えない）。
  **失敗したマクロの書き込みは出さない**（巻き戻っている、F-3-4）
- **`--out` には実行後の空でない全セルを書く。** 失敗したときや打ち切ったときは開始前のシートになる
- **時間の上限は既定 5 秒、`--timeout` で変えられる。** 超えたら Worker ごと捨て、
  stdout は `#Timeout`、終了コードは 1。**stderr に時間で打ち切ったことを書く**——ステップ数の
  上限（§7.8）の `#Timeout` は stderr が空なので、出力から見分けられる
  - 時間は Worker を起こしたときから数える。起動は数十ミリ秒で、既定の 5 秒に対して問題にならない
- **起動するメッセージはゴールデンテストの `!macro from: 1 to: 3`（ADR-0018）と同じ読み方をする。**
  同じ処理が 2 箇所に要るようになったので `core` の `readMacroMessage` に寄せた。
  1 つの送信として読めない `--send` は、仕様上のエラーではなく使い方の誤り（終了コード 2）
- **終了コードは `sec eval` と同じ 0 / 1 / 2。** 時間切れは 1、読めないファイル・JSON の誤り・
  書けない `--out` は 2

## 影響

- `packages/cli` に `sheet-file.ts`（JSON）、`macro.ts`（1 回の実行）、`macro-worker.ts` と
  `worker-host.ts`（時間の上限）が加わった
- `runCommand` は非同期になり、ファイルと Worker に触れる手段（`CommandHost`）を受け取る
- 開発方針の例を実際の形に合わせた
- M5（MCP）の試し実行（F-6）は同じ `executeMacro` と Worker を使える

## 覆すとしたら

- M7 で `.secbook` の形式が決まり、仮の JSON との違いが利用者の負担になったとき
- 5 秒が、実用のマクロで足りない、または CI で長すぎると分かったとき
- Worker の起動の時間が上限に対して無視できなくなったとき（数え始めを見直す）
