# ADR-0012: 数は整数（任意精度）と小数（倍精度）の 2 種とし、割り切れる除算は整数を返す

- 状態: accepted
- 日付: 2026-09-14
- 関連: 要件 F-2-7、仕様書 §0.3、§2.1、§6.1

## 背景

付録 B は「数値の内部表現と精度。整数と小数が混ざる演算の結果型を含む」を §6 送りに
していた。§6.1 で `Number` のセレクタ表を書くには、**`/` が何を返すか**と
**整数と小数が混ざったときの結果型**を先に決める必要がある。

§0.3 は表記だけを定めており（整数は小数点を付けない、小数は必ず付ける）、
`6 / 3` が `2` と `2.0` のどちらになるかは未定だった。

## 選択肢

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A | 整数（任意精度）と小数（IEEE754 倍精度）の 2 種。割り切れる `/` は整数 | 実装量が穏当。§0.3 の表記がそのまま使える | 返り値の型が値によって変わる |
| B | Smalltalk 流に分数を加えた 3 種 | `(1 / 3) * 3` が正確に `1` になる | `Fraction` の仕様と実装、§0.3 の表記が増える。M0 の分量が一段増える |
| C | 常に倍精度小数の 1 種（Excel 流） | 型が 1 つで規則が最も単純 | `1 + 1` が `2.0` になり、Smalltalk 風という看板から最も遠い |

## 決定

**A を採用する**（利用者の選択）。

- **整数は任意精度。** 表計算では ID や金額の桁が倍精度の安全域（2^53）を超えることがあり、
  **黙って桁が落ちるのが最も危険**だと判断した
- **小数は IEEE754 倍精度。** `0.1 + 0.2` が `0.30000000000000004` になることは
  受け入れ、`tests/golden/numbers.txt` で固定する。隠すと、隠しきれなかったときに
  かえって驚かれる
- **`/` は割り切れれば整数、そうでなければ小数。** `6 / 3` → `2`、`7 / 2` → `3.5`
- **整数と小数が混ざれば小数になる**（伝染）。`1 + 2.0` → `3.0`
- **`sqrt` は常に小数。** 一般に無理数になるため
- **`rounded` `truncated` は常に整数**
- **`//` `\\` は床除算**（Smalltalk-80）。剰余の符号は除数に合わせ、
  `self = (self // n) * n + (self \\ n)` が常に成り立つ
- **`1 = 1.0` は `true`。** 比較は値で行う

## 影響

- §6.1 の `Number` のセレクタ表がこの規則に従う
- §0.3 の値の表記に変更は要らない。整数と小数の 2 行がそのまま対応する
- 評価器は 2 つの内部表現を持つ。`core` は `lib: ["ES2023"]` なので `bigint` が使える
- **除算の返り値の型が値によって変わる**ため、仕様書の表には返り値の型を
  「整数または小数」と書く箇所が出る。§6.1 で明示する
- 付録 B の「数値の内部表現と精度」が解消される

## 覆すとしたら

- `(1 / 3) * 3` が `1` にならないことが実務で問題になると判明したとき → B（分数）へ。
  その場合 §0.3 に分数の表記が加わり、既存の `numbers.txt` の期待値が変わる
  （`1 / 3` の行）
