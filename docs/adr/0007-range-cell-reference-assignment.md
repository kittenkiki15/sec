# ADR-0007: 範囲リテラル・セル参照・セルへの代入の記法

- 状態: accepted
- 日付: 2026-09-14
- 対象: 要件定義書の未決論点 D-1 / D-2 / D-3

## 背景

言語仕様書（M0）を書くには、まず表計算に固有の 3 つの記法を決める必要がある。
この 3 つは文法の中核に触れるため、後から変えると字句解析器と構文解析器の
広い範囲を書き直すことになる。

## D-2 の決定: セル参照と変数名の区別

**`[A-Z]+[0-9]+` の形状を常にセル参照とみなし、その形の識別子を禁止する。**

`@A1` のような接頭辞を付ける案は採らない。表計算の数式では参照が最も頻出する要素であり、
そこに記号を足すと入力の手数と可読性の両方を損なう。

### この決定が D-1 に与える影響

当初「Excel の `A1:B10` はキーワードメッセージのコロンと衝突する」と考えていたが、
**D-2 を採ることでこの衝突は消える。**

- `A1` は識別子になれないため、`A1:` は変数への参照を伴うキーワード式になり得ない。
- この言語にユーザー定義クラス・メソッドは無く（要件 F-2 の範囲外）、
  組み込みセレクタはすべて小文字始まりの camelCase である。
- したがって **`A1:` が正当なキーワードセレクタになる経路が存在しない。**

コロンの前後に空白を許さないという規則を加えれば、字句解析で一意に決まる。

## D-1 の決定: 範囲リテラルの記法

**正準形を `A1 to: B10` とし、`A1..B10` と `A1:B10` をその糖衣構文とする。**

```smalltalk
A1 to: B10     "正準形。Cell>>to: が Range を返す"
A1..B10        "糖衣"
A1:B10         "糖衣。Excel 利用者向け"
```

- 正準形は Smalltalk のメッセージ式そのものであり、`Number>>to:` の語感とも揃う。
- **糖衣は構文解析の時点で `to:` のメッセージ送信へ脱糖する。**
  評価器に範囲専用のノードを持たせないため、意味論の定義が `to:` の 1 箇所で済む。
- 糖衣の区切り文字は**前後に空白を許さない**。`A1..B10` と `A1:B10` は可、
  `A1 .. B10` と `A1 : B10` は構文エラー。正準形は通常の空白規則に従う。

### パーサは常に 3 形式すべてを受け入れる

区切り文字の設定は**読める記法を変えない。** どの設定で書かれたブックも、別の設定の環境で
そのまま開ける。仕様書とゴールデンテストも設定に依存しない。

設定が影響するのは、**範囲をドラッグで選択したときに数式バーへ挿入される記法**と、
**ツールが数式を生成するときの記法**だけである。

保存済みの数式は影響を受けない。要件 F-5-1 のとおり数式は原文テキストのまま保持するため、
設定を変えても既存のブックの中身は書き換わらない。git で管理したときに設定の違いで
差分が出ることもない。

## D-3 の決定: マクロからのセル書き込み

**`B14 := total`。** セル参照への代入を特別扱いする。

```smalltalk
| total |
total := (B2 to: B13) sum.
B14 := total.
```

`Sheet at: #B14 put: total` は Smalltalk として素直だが、表計算のマクロで最も多い操作が
セルへの書き込みであることを踏まえ、短く読める方を採る。

**この代入はマクロでのみ許され、数式では構文エラーとする**（要件 F-2-10、数式は副作用を持てない）。

## コンフィグファイル

設定は**ユーザーの好み**として扱い、ブックには保存しない。「Excel に慣れているから
コロンで見たい」という種類の設定であり、文書の性質ではないため。

```json
{
  "range": {
    "delimiter": ".."
  }
}
```

- ファイル名は `sec.config.json`。
- `range.delimiter` の値は `".."` / `":"` / `"to:"` の 3 つ。既定は `".."`。
  正準形より短く、Excel の `:` と紛れないため。
- 設定が無い場合・ファイルが無い場合は既定値で動く。**設定ファイルは必須ではない。**

### 読み込みの責務

**`core` はコンフィグファイルを読まない。** `core` は Node API にもブラウザ API にも
依存しない（要件 N-8、ADR-0001）。ファイルの読み込みは `cli` / `mcp` が行い、
`web` は別の手段（インポートまたは IndexedDB）で用意する。
`core` は解決済みの設定をただのオブジェクトとして受け取る。

## 影響

- 字句解析器は `<セル参照>..<セル参照>` と `<セル参照>:<セル参照>` を
  それぞれ 1 つの範囲トークンとして切り出す（最長一致、空白を挟まないこと）。
- 構文解析器は範囲トークンを `to:` のメッセージ送信に脱糖する。
  **AST に範囲専用のノードを作らない。**
- ゴールデンテストは正準形 `to:` で書き、糖衣の等価性は専用のフィクスチャで確認する。
  設定に依存するケースは作らない。
- 代入の左辺がセル参照である場合の扱いを、数式とマクロで分ける必要がある。

## 覆すとしたら

- `A1:B10` の字句解析が、想定していなかった構文と衝突することが判明したとき
  → コロン形式だけを取り下げる（正準形と `..` は影響を受けない）
- ユーザー定義メソッドを導入することになったとき → `A1:` がセレクタになり得るか再検討する
- 設定項目が増えて `sec.config.json` の管理が重くなったとき → 形式と読み込み方法を見直す
