# ADR-0020: セル番地は「列の綴り + 行の数値」に正規化する

- 状態: accepted
- 日付: 2026-09-16
- 関連: [ADR-0007](0007-range-cell-reference-assignment.md)（D-2 のセル参照の形）、仕様書 §4.1、要件 F-1-3

## 背景

仕様書 §4.1 はセル参照の形を次の字句規則で定めている。

```ebnf
column         = "A" | ... | "Z" , { "A" | ... | "Z" } ;
row            = digit , { digit } ;
cell reference = column , row ;
```

**この規則は `A007` を受け付ける。** `row = digit , { digit }` は前ゼロを禁じていないし、
字句解析器（M1）は原文の綴り `"A007"` をそのままトークンに載せている。
しかし**その綴りがどのセルを指すかは、どこにも書かれていない。**
`docs/NEXT.md` は M3 の宿題として「`A007` と `A7` を同じセルと見るかはシートの側で決まる」
と記録したまま、未決で残していた。

**M3 の段階 1（シートモデル）に入るには、これを先に決めなければならない。**
番地が表のキーになる以上、「同じセルか」の判定はモデルの土台そのものだからである。

同じ問いは行の桁数にも及ぶ。§4.1 は「行の桁数に制限は無い」としているので、
行は任意精度で持てなければならない。

## 選択肢

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A | **行を十進数として読む。** `A007` は `A7` と同じセル | §4.1 をそのまま読んだ形。Excel も `A007` を `A7` に直す | 綴りと番地が 1 対 1 でなくなる |
| B | 前ゼロを `#Ref` にする | 綴りと番地が 1 対 1 に保たれる | §4.1 に無い規則が増える。「形としては正しいが指す先が無い」が `A0` 以外にも広がる |
| C | 前ゼロを字句の段階で弾き `#Syntax` にする | 評価まで届かない | **M1 の成果物に手を入れることになる。** §4.1 の字句規則を書き換えるので仕様変更になる |

## 決定

**A を採用する**（利用者の選択）。

- **番地は「列の綴り」と「行の数値」の組である。** 原文の綴りではない。
- **行は十進数として読む。** `A007` `A0007` `A7` はすべて同じセルを指す。
- **行は任意精度の整数で持つ**（§4.1 が桁数を制限していないため）。
  値の側で整数を `bigint` にしたのと同じ理由による（[ADR-0012](0012-number-model.md)）。
- **列は綴りがそのまま番地になる。** `A` `AB` は 26 進ではなく**双射基数 26**
  （`Z` の次が `AA`）なので前ゼロにあたる綴りが存在せず、正規化する余地がない。
- **`A0` は `#Ref` のまま**（仕様書 §4.2）。行が 1 始まりであること（要件 F-1-3）は
  番地の正規化とは別の規則であり、**正規化した結果が 0 なら解決できない**、と読む。

### 表記も正規化後の綴りになる

範囲の表記は正準形 `A1 to: B10` と定まっている（§4.3）。**その両端も正規化した番地で書く。**

```smalltalk
A007..A9    "→ A7 to: A9"
```

向きの正規化（`B10 to: A1` → `A1 to: B10`）が既に「原文の綴りをそのまま返さない」形に
なっているので、**前ゼロだけを原文どおりに残す理由が無い。**

## 影響

- `packages/core/src/model/` に置く番地の型が、列の綴りと行の `bigint` を持つ。
  原文の綴りは持たない。
- シートはこの番地をキーにする。**`A007` と `A7` は同じ 1 つのセルになる。**
- `tests/golden/references.txt` に前ゼロのケースを足す（M3 の段階 2）。
  既存のケースはすべて前ゼロを含まないため、期待値は変わらない。
- 仕様書 §4.1 に 1 段落を足す（M3 の段階 1 で行う）。**規則を変えるのではなく、
  §4.1 が書いていなかった「綴りから番地への読み方」を書き下ろす。**

## 覆すとしたら

- 絶対参照 `$A$1`（要件 F-1-4）や別シート参照 `Sales!A1`（F-1-7）を入れるとき、
  番地が持つ情報が増える。**そのとき番地の型は広がるが、この決定は覆らない**
  （前ゼロの読み方は直交している）
- 行・列の挿入／削除に伴う参照の自動調整（F-1-5）で、**数式の原文を書き換える**必要が出たとき
  → 原文の綴りを保つ要求が生まれる。ただしそれは「番地」ではなく「数式の原文」の話であり、
  書き換えの出力は正規化後の綴りでよい
