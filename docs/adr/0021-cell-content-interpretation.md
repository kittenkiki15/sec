# ADR-0021: 数式でないセルの内容はリテラルとして読み、読めなければ文字列にする

- 状態: accepted
- 日付: 2026-09-16
- 関連: [ADR-0009](0009-golden-sheet-directives.md)、[ADR-0010](0010-empty-cell-value.md)、
  要件 F-1-2、F-2-1、F-5-1、仕様書 §2

## 背景

セルの内容は**原文テキストで保持する**（要件 F-5-1、ADR-0009）。
`=` で始まればその残りを数式として評価する（要件 F-2-1）。

**決まっていないのは「`=` で始まらない内容をどう値にするか」である。**
要件 F-1-2 は「セルは数値 / 文字列 / 真偽値 / 空 / エラーのいずれかの値を持つ」としか言わず、
原文テキストからそのどれを作るかの規則が無い。

ゴールデンテストのフィクスチャは既にこの形を使っている。

```text
!A1 := 1        "整数の 1"
!A1 := 3.14     "小数の 3.14"
!A1 := 'abc'    "文字列の abc。引用符付きで書いてある"
!A1 := true     "真偽値"
!A1 := -5       "負のリテラル（§2.1）"
```

**M3 の段階 1（シートモデル）はこの変換を実装する段階なので、ここで決める。**

## 選択肢

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A | §2 のリテラルとして読む。読めなければ `#Syntax` | 書き方が 1 通りに定まる | `abc` と打つと `#Syntax` になり、表計算として使えない |
| B | **§2 のリテラルとして読む。読めなければ文字列** | 表計算の常識どおり `abc` が文字列になる。フィクスチャの書き方をそのまま活かせる | 同じ文字列に `'abc'` と `abc` の 2 通りの書き方が生まれる |
| C | `=` の有無に関わらず、常に数式として評価する | 規則が 1 つで済む | `1 + 2` が `3` になり、`abc` が `#Ref` になる。表計算の慣習から遠い |

## 決定

**B を採用する**（利用者の選択）。

**内容の読み方は次の 3 段で決まる。**

| 順 | 条件 | 結果 |
| --- | --- | --- |
| 1 | 内容が `=` で始まる | 残りを**数式**として構文解析・評価する（要件 F-2-1） |
| 2 | 内容が §2 のリテラルちょうど 1 つとして読める | そのリテラルの値 |
| 3 | それ以外 | **内容をそのまま持つ文字列** |

```text
=A1 + 1     "数式。A1 の値に 1 を足したもの"
1           "整数の 1"
'abc'       "文字列の abc"
true        "真偽値の true"
#foo        "シンボルの foo"
#(1 2 3)    "配列"
-5          "整数の -5（§2.1 の負のリテラル）"
abc         "文字列の abc。リテラルとして読めない"
1 + 2       "文字列の '1 + 2'。リテラル 1 つではない"
```

### 「リテラルちょうど 1 つ」とは

**§2 が定めるリテラルの構文に、内容全体が過不足なく一致することを言う。**
前後の空白は §1.1 のとおり無視する（`  1  ` は整数の 1）。

`1 2` や `1 +` は**リテラルが 1 つではない**ので段 3 に落ち、文字列になる。
「途中まで読めた分を採る」ことはしない。**部分一致を許すと、`1 abc` が `1` になるか
`'1 abc'` になるかを別途決めることになる。**

### リテラルとして読めても値がエラーになることがある

**段 2 に入るかどうかは構文で決まり、値がエラーかどうかは関わらない。**

```text
1.0e400     "→ #Overflow。§2.1 の形には合うが倍精度に収まらない（ADR-0013）"
```

これは文字列 `'1.0e400'` にはならない。**エラーもセルが持てる値である**（要件 F-1-2）。

### 空の内容は空セル

**内容が空文字列のセルは「空」であり、値は `nil`**（[ADR-0010](0010-empty-cell-value.md)）。
段 2 の「リテラルちょうど 1 つ」にも当たらないが、段 3 の文字列にもしない。
**空文字列を値として持つセルと、空のセルは別物である**（前者は `''` と書いて作る）。

### 2 通りの書き方が生まれることを受け入れる

`'abc'` と `abc` はどちらも文字列 `abc` になる。
ADR-0009 はゴールデンテストの**ディレクティブ**について「同じことに 2 通りの書き方を
作らない」として `=` だけの区切りを拒否したが、**ここはその判断と衝突しない。**
拒否したのは**フィクスチャを書く側の記法**で、ここで決めているのは**利用者がセルに打つ
文字列の解釈**である。**利用者に引用符を強いる表計算は存在しない。**

**フィクスチャの側では引用符付きの形だけを使う。** 既存のケースはすべてその形であり、
新しいケースもそれに揃える。**段 3 を通る内容をフィクスチャに書くのは、
段 3 そのものを検査するケースに限る。**

## 影響

- `packages/core/src/model/` に「内容の原文 → 値」の変換を置く。
  段 1 と段 2 は既存の構文解析器（`parseFormula`）で足り、**新しい構文は要らない。**
- **`Sheet` は原文を保持する**（要件 F-5-1）。値は再計算の結果として別に持つ。
  `.secbook` の保存・読み込み（F-5-1）と、数式バーが原文を出せること（F-7）が
  これに依存する。
- ゴールデンテストのディレクティブ `!A1 := 内容` は、この規則で値になる。
  **ハーネス側の変更は無い**（ADR-0009 の時点で内容は原文テキストのまま渡している）。
- 仕様書に節を足す（M3 の段階 1）。§4 はセル参照の**評価**を定めており、
  **セルの内容の解釈**はまだどこにも書かれていない。
- Web UI（M6）は、利用者が打った文字列をそのまま内容にすればよい。
  **引用符を補う処理を UI に持たせない。**

## 覆すとしたら

- 日付・時刻（要件 F-2-12）を入れるとき。`2026-09-16` と打った内容を日付にするなら
  段 2 と段 3 の間に「日付として読めるか」の段が要る
- 数値フォーマット（F-1-6）を入れるとき。`1,000` や `50%` を数として読みたくなる。
  **そのときも段の順序は変わらず、段が増えるだけである**
- 段 3 を通る内容が実際に増え、`'abc'` と `abc` の食い違いが事故を生んだとき
  → 案 A に寄せる。ただし**その事故は UI の入力経路で起きるので、
  先に UI の側で吸収できないかを見る**
