# ADR-0003: ゴールデンテストのファイル形式

- 状態: accepted
- 日付: 2026-09-14

## 背景

開発方針の中核は「仕様を実行可能にする」ことで、その実体が `tests/golden/*.txt` である。
人間が差分で読めて、Claude Code が機械的に追加でき、Smalltalk の構文と衝突しない形式が要る。

## 選択肢

| 案 | 内容 | 欠点 |
| --- | --- | --- |
| A | `式 => 期待値` を 1 行に書く | 式や期待値に `=>` を含むと曖昧。複数行の式が書けない |
| B | JSON / YAML に構造化する | 差分が読みにくい。Smalltalk の式を引用符でくるむ必要があり、エスケープが要る |
| C | 空行区切りのブロック。`=>` で始まる行から後ろが期待値 | 区切りの規則を覚える必要がある |

## 決定

**C を採用する。**

```text
"行頭が二重引用符の行はコメント（Smalltalk のコメントに合わせている）

3 + 4 * 2
=> 14

"式も期待値も複数行に書ける
| a |
a := 3.
^ a + 1
=> 4
```

- 空行がケースの区切り。
- ケース内で最初に現れる `=>` で始まる行から後ろが期待値。
- 行末の空白は無視する。

Smalltalk の式が行頭から `=>` で始まることはないため、区切りは曖昧にならない。
コメント記号に `#` を使わないのは、`#(1 2 3)` や `#DivideByZero` と衝突するため。

ハーネスは `packages/core/src/testing/golden.ts`。
ファイル読み込みを含まない純粋な文字列処理とし、core が Node API に依存しないようにしている。

## 影響

- 構文や組み込みセレクタを追加・変更したら、対応するゴールデンテストを必ず追加・更新する。
- **実装を通すために期待値を書き換えない。** 期待値の変更は仕様変更であり、ADR が要る。
- 言語仕様書（`docs/02-language-spec.md`）は、節ごとに対応するフィクスチャ名を明記する。

## 覆すとしたら

- 1 つのケースに複数の入力シート状態を与える必要が出て、平文では表現しきれなくなったとき
  → シート状態だけを別ファイルに切り出し、ケースから参照する形に拡張する
  （形式そのものは変えず、前置きのディレクティブを足す方向で検討する）
