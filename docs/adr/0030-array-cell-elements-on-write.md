# ADR-0030: セルに書き込む配列の要素の `Cell` は値まで解決する

- 状態: accepted
- 日付: 2026-09-24
- 関連: 仕様書 §4.2・§6.3・§7.4、[ADR-0015](0015-range-enumeration.md)、
  [ADR-0027](0027-macro-execution.md)、[#72](https://github.com/kittenkiki15/sec/issues/72)

## 背景

M4 の段階 4（[#72](https://github.com/kittenkiki15/sec/issues/72)）でセルへの代入を実装するとき、
**`Cell` を要素に持つ配列をどう置くか**が決まっていないことが分かった。

ADR-0027 は右辺が `Cell` なら値まで解決して置くと決めたが、配列の要素には触れていない。
範囲の列挙が渡すのは `Cell` なので（ADR-0015）、**`collect:` の結果はセルを要素に持ちうる。**

```smalltalk
"B1 = 1, B2 = 2 のとき"
A1 := (B1 to: B2) collect: [:c | c].   "要素は Cell。表記は #(1 2)"
B1 := 10.
^ A1                                    "#(1 2) か、それとも別の結果か"
```

§0.3 はセルの表記を保持する値に従わせるので、この配列は `#(1 2)` と表記される。
内容として置いて読み戻せば値の配列になり、**元のセルは追わない。**

## 選択肢

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A | **値まで解決して置く。** 要素の値がエラーなら、そのエラーでマクロが終わる | 最上位の `Cell` と同じ規則。表記どおりのものが書き込まれる | 要素がセルであることが書き込みで消える（最上位と同じ） |
| B | `#TypeError` にする。リテラルで書けない要素として拒む | 置かれるものが表記と一致しない余地を残さない | 表記の上では `#(1 2)` なのに書けない。`collect: [:c \| c value]` と書き直す手間がかかる |

## 決定

**案 A を採る**（利用者の選択）。

- **配列の要素の `Cell` も、最上位の `Cell` と同じく保持する値に置き換えてから置く。**
  入れ子の配列の中でも同じ。書いた後は元のセルを追わない。
- **要素の値がエラーなら書き込まず、そのエラーでマクロが終わる。** エラーを要素に持つ
  配列を書き込めない（ADR-0027）のと同じ規則が、解決した後の値に当たる。
- ブロック・範囲・区間は要素であっても `#TypeError`。リテラルで書けない（ADR-0027）。
- 書き込み先のセル参照を解決できない（行が 0）ときは `#Ref`。読むときと同じ（§4.2、ADR-0020）。
  これは既存の規則の帰結で、新しい選択ではない。

## 影響

- 仕様書 §7.4 の表と付録 A に書く。
- `assignment.txt` に決定を固定するケースを足した。

## 覆すとしたら

- 要素がセルのまま残ることを前提にした処理（セルの配列を後で `value` し直すなど）を
  書き込み越しに持ち回りたい要求が出たら、案 E（ADR-0027）と一緒に見直す。
