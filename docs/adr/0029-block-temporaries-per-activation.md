# ADR-0029: ブロックの一時変数は起動ごとに作る

- 状態: accepted
- 日付: 2026-09-24
- 関連: 仕様書 §7.3・§7.5、[ADR-0027](0027-macro-execution.md)、
  [ADR-0028](0028-temporary-holds-cell.md)、[#68](https://github.com/kittenkiki15/sec/issues/68)

## 背景

M4 の段階 2（[#68](https://github.com/kittenkiki15/sec/issues/68)）でマクロのブロックの
一時変数（§7.5）を実装するとき、**その一時変数がいつ作られるか**が仕様書にも ADR にも
無いことが分かった。

```smalltalk
| f |
f := [:n | | t | t := n. n = 0 ifTrue: [0] ifFalse: [(f value: n - 1) + t]].
^ f value: 3     "6 か 0 か"
```

ブロックは一時変数を通して自分を呼べる（ADR-0027）。**再帰の各段が同じ `t` を使うと、
内側の起動が外側の `t` を書き換える**ので、この例の答えが変わる。

## 選択肢

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A | **ブロックを起動するたびに新しく作る** | 再帰の各段が自分の一時変数を持つ。上の例は `6`。現在の Smalltalk（Pharo、ANSI）と同じ | 起動ごとに束縛を作る費用がかかる |
| B | ブロックの値ごとに 1 組を作って共有する | 作る費用がかからない。Smalltalk-80 の原典の形 | 再帰で一時変数を使うと壊れる。上の例は `0`。前の起動の値が次の起動に残る |

## 決定

**案 A を採る**（利用者の選択）。

- **ブロックの一時変数は起動ごとに新しく作り、`nil` から始まる。** 前の起動で書いた値は残らない。
- **外側の一時変数は共有する。** 何度起動しても、どの起動からも同じものを読み書きする（§7.5）。
  引数を取るブロックからの書き込みも外側に届く。
- 実装は名前ごとの入れ物（`Binding`）を束縛の表に置く。起動のたびに表を写しても、
  写した表どうしが外側の同じ入れ物を指す。

## 影響

- 仕様書 §7.5 に「一時変数は起動ごとに作る」を足し、付録 A に行を足す。
- `macros.txt` に決定を固定するケースを足した。一時変数を共有する実装では `6` にならないケースと、
  前の起動の値が残らないケースである。

## 覆すとしたら

- 起動ごとに束縛を作る費用が性能要件（N-1・N-2）に効くと計測で分かったら、写し方を見直す。
  **見直すのは実装であって、意味（案 A）は変えない。**
