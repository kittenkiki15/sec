# ADR-0027: マクロの実行（エラーで終わる時点・書き込みの届き方・値の置き方・上限の分担）

- 状態: accepted
- 日付: 2026-09-24
- 関連: 要件 F-3-3〜F-3-7・F-4-2・F-4-4・F-5-1・N-5、仕様書 §7、
  [ADR-0010](0010-empty-cell-value.md)、[ADR-0011](0011-error-propagation-order.md)、
  [ADR-0021](0021-cell-content-interpretation.md)、[ADR-0024](0024-incremental-invalidation.md)、
  [#27](https://github.com/kittenkiki15/sec/issues/27)、[#64](https://github.com/kittenkiki15/sec/issues/64)

## 背景

仕様書 §7 はマクロの文法と意味論を定めたが、**実行の側で決まっていない論点が 5 つ残っていた。**
M4 の段階 0（[#64](https://github.com/kittenkiki15/sec/issues/64)）で、着手前に利用者と決めた。

1. **マクロがエラーで終わるのはどの時点か。** §7.4 が定めたのは「セルへの代入の右辺が
   エラーなら終わる」だけで、`1 / 0. ^ 3` のように値を捨てる文については何も言っていない。
2. **途中で数式セルを読んだとき、同じマクロの書き込みが反映されるか。**
   §7.4 は「書き込んだ値は同じマクロの中で読み直せる」と定めたが、下流の数式については
   「要件 F-4 が定める」として外に出していた。
3. **書き込んだ値をどうセルに置くか。** シートは原文だけを持つ（M3 段階 1）。値を原文に
   直す方法を決めなければ、`'3'` を書き込んだセルが数 3 として読み戻される。
4. **時間上限（要件 F-3-5）をどこで掛けるか**（#27）。
5. **マクロから他のマクロを呼ぶ機能（F-3-7）を M4 に含めるか。**

## 選択肢

### 1. エラーで終わる時点

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A | **どの文でも値がエラーになったら終わる** | エラーを黙って捨てる経路が無い。ADR-0011 の「最初に生じたエラー」と揃う | 値を捨てる文でも止まる |
| B | セルへの代入と `^` の値がエラーのときだけ終わる | Smalltalk の「式文の値は捨てる」に近い | `a := 1 / 0` を抱えたまま先へ進めてしまう |

### 2. 書き込みが下流に届くか

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| C | **届く。** 書き込みは下流の値を捨てるだけにし、読まれたときに計算する | 読みが常に整合する。何度書いても下流を計算し直すのは読まれた分と最後の 1 回だけ | 再計算を「捨てる」と「確定する」に分ける必要がある |
| D | 届かない。マクロが成功して反映するときに 1 回だけ再計算する | 実装が単純 | 書いた直後に下流が古く見える。§7.4 の「読み直せる」と食い違って見える |

### 3. 値の置き方

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| E | **§0.3 のリテラル表記で原文として置く。** リテラルで書けない値は `#TypeError` | シートが原文だけを持つ形を崩さない。保存（F-5-1）もそのまま | ブロック・範囲・区間は書き込めない |
| F | セルに原文とは別に値を持たせる | どんな値も置ける | 原文と値の 2 通りの持ち方ができ、保存・数式バー・再計算のすべてが分岐する |

### 4. 時間上限の置き場所

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| G | **ホスト側（Web UI / MCP / CLI）で掛ける。** `core` はステップ数と再帰深度だけを数える | `core` が決定的なまま（F-4-4）。時刻を読む経路が評価器に無い（規約 5） | `core` を直接使う呼び出し側は時間では止まらない |
| H | `core` に時計を注入して時間でも打ち切る | 1 箇所で済む | 同じ入力でもマシンの速度で結果が変わる。`#Timeout` のケースをゴールデンテストに書けない |

## 決定

**A・C・E・G を採り、マクロ呼び出しは M4 に含めない**（すべて利用者の選択）。

### エラーで終わる時点（案 A）

**文の値がエラーなら、その文の列はそこで打ち切られ、そのエラーが列の値になる。**

- マクロ本体では、**そのエラーでマクロが終わる**（書き込みは巻き戻る、F-3-4）。
- ブロック本体では、**そのエラーがブロックの値になる。** 後は §6.0 のとおり送信の値として
  伝わるので、`[1 / 0. 2] value` を返す文もそのエラーでマクロを終える。
- 代入の右辺がエラーなら代入しない。**一時変数への代入でも同じ**で、エラーを変数に抱えて
  先へ進めない。
- `do:` のブロックの値がエラーなら、`do:` の値はそのエラーになる。`collect:` と同じ（§6.0）。

### 書き込みが下流に届く（案 C）

```
シート: A1 = 1, B1 = =A1 + 1, C1 = =B1 * 2
マクロ: A1 := 5. ^ B1
```

| 時点 | すること |
| --- | --- |
| 開始 | トランザクションを開き、空の取り消し記録を用意する |
| `A1 := 5` | A1 の元の原文を控える（そのセルへの最初の書き込みだけ）。原文を置き換え、**A1・B1・C1 の値を捨てる。計算はしない** |
| `^ B1` | B1 に値が無いので、その場で `=A1 + 1` を評価して 6。C1 は読まれないので計算しない |
| 成功 | 捨てたままのセルをまとめて計算して確定する。計算し直した番地を返す（UI の描き直し） |
| 失敗 | 取り消し記録の原文を書き戻し、値を捨てて確定する。**シートは開始前と同じ値に戻る** |

- **読みは常に整合する。** 途中のどの時点で読んでも、その時点の原文で全体を計算し直した値と同じ
  ——`LiveSheet` が今も守っている不変条件である。
- **ADR-0024 の分担は動かさない。** 無効化は今までどおり実際に読んだ番地の記録で決める。
  変わるのは、捨ててから計算するまでの間を空けられるようにすることだけである。
- **控えるのは原文**なので、書き込み先にあった数式もそのまま戻る。
- マクロ自体はセルではないので、**マクロの読みは依存として記録しない**（`sec eval` の式と同じ）。

### 値の置き方（案 E）

**書き込む値は §0.3 の表記で原文にし、ADR-0021 の読み方で同じ値に戻ることを保証する。**

| 値 | 置き方 |
| --- | --- |
| 数・真偽値・シンボル | §0.3 の表記そのまま。小数は同じ倍精度に戻る表記（ADR-0017） |
| 文字列 | **常に引用符付き**（`'3'`・`'=B1'`・`'it''s'`）。素のまま置くと数や数式として読まれうる。Excel が先頭の `'` で文字列を示すのと同じ発想 |
| 配列 | §0.3 の表記。**要素にエラーがあれば、そのエラーでマクロが終わる**（下記） |
| `nil` | **セルを空にする。** 空の内容を置くことはセルを空にすること（ADR-0010、M3 段階 1）で、`nil` の持ち方を 2 通りにしない |
| セル | **値まで解決してから置く**（`heldValue`）。セルそのものは置かない |
| ブロック・範囲・区間 | **`#TypeError`。** リテラルで書けない |
| エラー | 右辺がエラーなら書かない（§7.4）。上の案 A と同じ |

**エラーを要素に持つ配列を書き込めない**のは、表記が別の値に読み戻されるからである。
`#(1.0e400)` は `#(#Overflow)` と表記されるが、原文として置くと**シンボルの配列**として読まれる。
表記の問題を直すのではなく、**エラーを値としてセルに残さない**（§7.4）という既存の規則を
配列の要素にも当てる。

### 上限の分担（案 G）

| 上限 | どこで | 超えたら |
| --- | --- | --- |
| ステップ数 | `core`（既存の `StepBudget`） | `#Timeout` |
| **再帰深度** | **`core`。明示的な上限を入れる** | `#Timeout` |
| 時間 | **マクロを実行するすべてのホスト**（Web UI は Worker、MCP と CLI の `sec run` はスレッドかプロセス） | ホストが打ち切り、`#Timeout` として報告する |

- **時間の上限を掛けるのは、マクロを実行するすべてのホストである。** Web UI・MCP サーバー
  だけでなく、**CLI の `sec run`（M4 段階 8）も含む。** 要件 F-3-5 は実行の入口を区別しておらず、
  入口ごとに止まったり止まらなかったりすれば、同じマクロの扱いが入口で変わる。
- **ホストはマクロを隔離した単位（Worker・スレッド・子プロセス）で、シートの写しに対して動かし、
  最後まで走ったときだけ結果を反映する。** 時間を超えたら単位ごと捨て、`#Timeout` として報告する。
  **何も反映していないので、巻き戻しはそれだけで成り立つ**（F-3-4）。`core` の取り消し記録は
  評価器の中で終わる失敗（エラー値・ステップ数・再帰深度）のためのもので、外から打ち切られた
  実行はそこに頼らない——打ち切られた時点の記録は完全である保証が無い。
- **`#Timeout` の種別は `core` の上限と同じ**（§7.8）。利用者から見て、止まった理由が
  ステップ数か時間かで扱いを変える必要は無い。
- **再帰深度の上限は M4 で入れる。** マクロ呼び出しを入れなくても、**ブロックは一時変数を通して
  自分を呼べる**（`f := [:n | f value: n + 1]`）。数式では代入が書けないので起きなかった形で、
  **JavaScript のスタックが尽きるのを待つ安全網（#27）では上限にならない。**
- **上限の値は M4 の後の段階で、要件 N-1〜N-3 と併せて決める**（§7.8）。本 ADR は機構の
  置き場所だけを決める。
  **値と再帰深度の数え方は [ADR-0033](0033-execution-limit-values.md) で決めた。**

### マクロ呼び出し（F-3-7）は M4 に含めない

完了条件（要件定義書 §8）に無く、ブックへの保存（F-3-1）とも絡む。
**再帰深度の上限は上記のとおりブロックのために入るので、呼び出しを足すときに上限の側は要らない。**

## 影響

- **仕様書 §7.2・§7.4・§7.5・§7.8 に書く。** §7.4 の「右辺がエラーなら」は案 A の特例になる。
- **`Recalculation.update` を「値を捨てる」と「確定する」に分ける**（セルへの代入の段階）。
  `LiveSheet` の外から見た振る舞いは変えない。
- ゴールデンテストに決定を固定するケースを足した（`macros.txt` のエラーで終わる節と
  再帰の 2 件、`assignment.txt` の値の置き方と下流に届く節。すべて `!pending m4`）。
  **巻き戻しはゴールデンテストでは観測できない**（マクロの値しか書けない、ADR-0018）ので、
  単体テストで固定する。

## 覆すとしたら

- **値を捨てる文でエラーを無視したい場面**が実際のマクロで多いと分かったら、案 A を見直す。
  その場合も先にエラーの捕捉（未決論点 D-8）を決めるのが筋で、黙って捨てる方へは戻さない。
- **ブロックや範囲をセルに置きたい要求**が出たら案 E を見直す。スピル（D-4）と一緒に決める。
- ホストを経由せずに `core` を直接使う利用者が現れ、時間で止める必要が出たら案 G を見直す。
- 隔離した単位に写しを渡す費用がシートの大きさに対して重すぎると分かったら、
  打ち切り時の巻き戻しの手段を見直す（要件 N-1〜N-3 の計測で判断する）。
