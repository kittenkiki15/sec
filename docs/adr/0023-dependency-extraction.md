# ADR-0023: 依存は静的に抽出し、正しさは遅延の安全網が持つ

- 状態: accepted
- 日付: 2026-09-17
- 関連: 要件 F-4-1〜3、仕様書 §4.2、§4.3、[ADR-0008](0008-cell-value-delegation.md)、[ADR-0015](0015-range-enumeration.md)、[ADR-0024](0024-incremental-invalidation.md)

## 背景

M3 段階 5（[#54](https://github.com/kittenkiki15/sec/issues/54)）で、**数式セルの値を出す**。
そのためには読む順序が要る。`B1` が `=A1 + 1` なら、`A1` の値が先に決まっていなければならない。

要件は 3 つを求めている。

- **F-4-1**: 数式からセル参照を抽出し、依存グラフを構築する
- **F-4-2**: トポロジカル順序で評価する（増分再計算は段階 6）
- **F-4-3**: 循環参照を検出し、関与セルを `#Circular` にする

**依存は数式の木から読める**——ように見える。`A1 + 1` は `A1` を読み、`A1..A3 sum` は
矩形の中を読む。**しかし木だけでは決まらない形がある。**

```smalltalk
"範囲の端が式であれば、どの矩形になるかは評価するまで決まらない"
(A2..A2 detect: [:c | true] ifNone: [nil]) to: C4
```

列挙が渡す要素は `Cell` なので（ADR-0015）、**ブロックの中でセルが値として動き回る。**
そこから作られた範囲の矩形は、木に綴りとして現れない。**静的な抽出は取りこぼしうる。**

## 選択肢

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A | **静的抽出＋遅延の安全網** | 要件の字面どおりグラフを組める。取りこぼしても値は正しい | 2 つの機構を持つ |
| B | 動的記録だけ（読んだ番地をその場で依存にする） | 取りこぼしが原理的に無い。最小 | F-4-1 が評価の副産物になる。短絡する列挙（`detect:ifNone:`）は**読まなかったセルを依存に数えない**ので、段階 6 の増分再計算で穴が残る |
| C | 静的抽出だけ | 機構が 1 つ | 上の形で**順序を誤り、循環を見落とす。** 取りこぼす形をフィクスチャで固定して「本書では定めない」と書く前提になる |

## 決定

**A を採用する**（利用者の選択）。

- **順序は静的な依存グラフが決める。** 数式の木からセル参照と矩形を集め、
  トポロジカル順序に並べてから評価する（`dependencies.ts`）。
- **正しさは遅延と進行中の印が持つ。** 値は求められたときに求め、
  **求めている最中のセルを読み直したら参照が巡っている**（`recalc.ts`）。

**抽出は差し替えられる**（`RecalculationOptions.dependencies`、利用者の要望）。
段階 7 の `sec bench` が性能要件（N-1〜N-3）を測ったとき、**抽出の方式が解決策になりうる。**

### 静的な抽出が順序しか決めないこと

**この分担がこの決定の要点である。** 抽出が何を返しても値は変わらない——変わるのは
評価の順序と再帰の深さだけである。**依存を 1 つも返さない抽出でも、値は正しく出る。**
これは単体テストで固定してある（`recalc.test.ts`）。

したがって、

- **取りこぼしても壊れない。** 順序が悪くなるだけで、安全網が巡りを見つける。
- **多めに取っても壊れない。** `A1..A3 size` は矩形の大きさしか使わないが、
  抽出は矩形の中の数式セルすべてを依存として数える。順序が増えるだけである。
- **差し替えが安全である。** 方式を変えても仕様上の振る舞いは動かない。

### 循環を静的グラフで判定しない理由

トポロジカル順序に載らなかったセルを**そのまま `#Circular` にはしない。**
載らない理由は 2 つあり、**片方は循環ではない**ためである。

- 本当に巡っている（`=A1` が `A1` にある）
- **多めに取った依存で巡って見える**（`=A1..A3 size` は `A1` を読まないが、矩形には入る）

**評価してみれば区別が付く。** 実際に読んだときだけ進行中の印に当たるので、
`=A1..A3 size` は値が出て、`=A1..A3 sum` が `#Circular` になる。
**静的に決めると、この 2 つが同じ扱いになる。**

### 受け手のセルは引数より先に解決される

**この決定と一緒に、§4.2 の解決の時期を明示した**（利用者の選択）。

```smalltalk
"A1 が =A1 のとき"
A1 + (1 / 0)   "→ #Circular。#DivideByZero ではない"
```

§6.0 の伝播順序は「受け手 → 引数を左から右 → 送信」で、**受け手のセルが先に評価される**
とは「受け手の値がエラーなら引数に到達しない」ということである。
`A0 + (1 / 0)` が `#Ref` になるのと同じ順序で、`errors.txt` が M0 から固定していた。

**規則 1（`value` / `to:`）では解決しない**ので、§4.3 の「範囲はセルの値を読まない」は
そのままである。循環しているセルからも範囲は作れる。

```smalltalk
"A1 が =A1 のとき"
A1..A3 size    "→ 3。矩形の大きさは値を読まずに決まる"
A1..A3 count   "→ #Circular。nil でない要素を数えるので読む"
```

**循環を「参照そのもののエラー」（`#Ref` と同列）にはしなかった。** そうすると
セル参照を評価した時点で値が要り、**範囲を作るだけで両端を読む**ことになる。

## 影響

- `packages/core/src/model/dependencies.ts`（抽出）と `recalc.ts`（順序と評価）。
  `sheetValues` は `recalculate` に置き換わる
- **`Sheet` が番地を列挙できるようになる**（`addresses`）。グラフの節点を作るのに要る
- **構文解析と評価を分けて呼べるようにした**（`parseFormulaOrFail` / `evaluateParsedFormula`）。
  再計算は同じ木を抽出と評価の両方で使うので、原文から評価し直すと全数式を 2 度解析する
- 仕様書 §4.2 に「受け手は引数より先に解決される」を書き、§4.3 に循環との関係を書く
- ~~段階 6 の増分再計算は、**この静的グラフの逆向き**（依存されている側 → 依存する側）を使う~~
  → **そうしなかった**（[ADR-0024](0024-incremental-invalidation.md)）。取りこぼしは
  フル再計算では順序の粗さでしかないが、**増分では「古い値が残る」形で表に出る。**
  無効化は実際に読んだ番地の記録で決める。**順序をこの静的グラフが決めることは変わらない**

## 覆すとしたら

- **段階 7 の `sec bench` が抽出の粗さを問題にしたとき** → `RecalculationOptions` から
  別の抽出を渡す。矩形を丸ごと 1 つの依存にする今の形は、**大きな範囲を持つシートで
  節点あたりの辺が増える。** 使う分だけに絞る抽出や、矩形を索引で引く形に差し替えられる
- ~~**段階 6 で、動的に読んだ番地を記録する必要が出たとき** → 抽出を評価の副産物にする
  （案 B）。そのときも安全網は残るので、**順序の出所が変わるだけである**~~
  → **段階 6 で記録が要ることが分かった**（ADR-0024）。ただし抽出は評価の副産物にしていない。
  **記録は無効化にだけ使い、順序は静的な抽出が決めたままである**——役割が違えば、
  取りこぼしたときに起きることも違う
