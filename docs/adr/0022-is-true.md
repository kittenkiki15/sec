# ADR-0022: `isTrue` はすべての値が理解する

- 状態: accepted
- 日付: 2026-09-17
- 関連: 仕様書 §6.2、§6.3、[ADR-0008](0008-cell-value-delegation.md)、[ADR-0010](0010-empty-cell-value.md)

## 背景

M3 段階 4（[#49](https://github.com/kittenkiki15/sec/issues/49)）で、
**ブロックが `Cell` を返したとき条件として読めるか**が論点として残った。

```smalltalk
A1..A3 select: [:c | c]   "→ ?"
```

**`#TypeError` のままとすることが決まった**（利用者の判断）。委譲（§4.2 の規則 2）は
**メッセージの送信に対する規則**であって、ブロックの値を条件として読むのは送信ではない。
§6.3 が「列挙のブロックは真偽値を返さなければならない」と定めており、`Cell` は真偽値ではない。

**そのぶん、セルを条件にする明示的な手段が要る。** 範囲を条件で絞るのは表計算の基本的な
操作であり（要件 F-2-7 の `select:`）、**手段が無いままでは規則だけが残る。**

**能力そのものは既にある。** `=` は受け手のクラスを選ばず、セルは委譲で値に解決されるので、
`A1..A3 select: [:c | c = true]` は今日も動く。**したがって決めるのは新しい能力ではなく、
読みやすい綴りをどこに置くかである。**

## 選択肢

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A | **すべての値が理解する**（`isNil` と同じ列） | セルは委譲で動く。値の配列にも使える。§4.2 の不変が保てる | 真偽値でない値を `false` に畳む |
| B | `Cell` 自身のセレクタにする | 「セルを条件にする」という意図が型に出る | `true isTrue` が `#DoesNotUnderstand`。委譲の境界が広がる |
| C | 真偽値と `nil` だけが理解する | 真偽性を一切持ち込まない | 範囲に数や文字列が混ざると `select:` 全体がエラーになり、目的に使えない |

## 決定

**A を採用する**（利用者の選択）。

- **受け手が `true` のときだけ `true`、それ以外はすべて `false`。**
- **`isNil` / `notNil` と同じ扱い**（§6.2）。受け手を選ばずに送れる。

### `Cell` 自身のセレクタにしない理由

**§4.2 の「`Cell` が理解するのは `value` と `to:` だけ」は load-bearing である。**
規則 1（`Cell` 自身が理解する）と規則 2（保持する値へ委譲する）の分かれ目がこの一覧で、
**増やすたびに委譲されないセレクタが増える。**

委譲に任せれば、**セルでも値でも同じ式が書ける。**

```smalltalk
A1..A3 select: [:c | c isTrue]                    "範囲。要素は Cell"
(A1..A3 collect: [:c | c value]) select: [:v | v isTrue]   "値の配列"
```

B ではこの 2 行目が `#DoesNotUnderstand` になる。**列挙の結果は常に `Array` なので**
（§6.3）、セルだけが理解する形は列挙を 1 段通るたびに使えなくなる。

### 真偽値でない値を `false` に畳むこと

**これがこの決定の代償である。** `1 isTrue` は `false` で、`#DoesNotUnderstand` ではない。

**「`false` 以外を真とみなす経路」は作っていない。** §6.3 と §7.6 が定めるのは
**条件として読む側の規則**で、そこは変えていない。

```smalltalk
1 ifTrue: ['真']                 "→ #DoesNotUnderstand。受け手が真偽値でない"
1 and: [true]                    "→ #DoesNotUnderstand"
#(1 2) select: [:x | x]          "→ #TypeError。ブロックの値が真偽値でない"
```

**`isTrue` は明示的な問い合わせであり、暗黙の変換ではない。** 書き手が「真か」を尋ねたのに
対して答えているだけで、**尋ねていない場所で値が真偽値として扱われることはない。**
`isNil` がすべての値に答えるのと同じ形である。

**答えは `= true` と一致する。** 別の意味論を持ち込んでいないことが、ここで確かめられる
（`=` を理解しないブロックだけが例外で、`[1] isTrue` は `false`、`[1] = true` は
`#DoesNotUnderstand`）。

## 影響

- **§6.2 の `Boolean` の表に `isTrue` を足す。** すべての値が理解することも併記する
- **§6.3 の「列挙のブロックは真偽値を返さなければならない」に `Cell` の場合を書く。**
  `#TypeError` であることと、`isTrue` を送れば条件にできることの両方
- 付録 A に 2 行足す（`Cell` を条件として読むか／`isTrue` の置き場）
- `isFalse` は入れない。`not` を送れば足りる（`c isTrue not`）。
  **2 回目に必要になるまで抽象化しない**（CLAUDE.md）

## 覆すとしたら

- **真偽値でない値に `isTrue` を送る誤りが実際に起きたとき** → C（真偽値と `nil` だけ）へ
  寄せる。そのときは `A1..A3 select: [:c | c isTrue]` が空セル以外の非真偽値でエラーに
  なるので、**範囲を絞る別の手段**（`select:` の前に型で絞る形）が併せて要る
- **`Cell` を条件として読めるようにする判断に変わったとき**（§7.6 の `whileTrue:` を
  書く M4 が再考の機会）→ `isTrue` は短縮形として残る。どちらの決定とも両立する
