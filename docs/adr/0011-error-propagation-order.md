# ADR-0011: 複数のエラーが同時に生じたときは、評価順で最初のものが伝播する

- 状態: accepted
- 日付: 2026-09-14
- 関連: 要件 F-8-1、F-8-2、仕様書 §3.6、§3.7

## 背景

§3.7 は「上流のエラーは下流へ伝播する」とだけ述べており、**受け手と引数の双方が
エラーになる場合にどちらが返るかを定めていなかった。**

```smalltalk
(3 foo) + (1 / 0)   "#DoesNotUnderstand か #DivideByZero か"
```

付録 B はこれを §6 送りにしたうえで、**「これが決まるまで §3.6 の評価順序を
ゴールデンテストで固定できない」**と書いていた。純粋な数式では、エラーがどれになるか
以外に評価順序を観測する手段が無いためである。段階 3 で §6 を書くにあたり、
これを先に決める。

## 選択肢

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A | 評価順（受け手 → 引数を左から右 → 送信）で**最初に生じたエラー**を返し、以降は評価しない | Smalltalk の例外が巻き戻す順序と同じ。§3.6 以外に新しい規則が要らない | 複数のエラーがあっても 1 つしか見えない |
| B | エラーの種別に優先順位を付ける（`#Syntax` > `#Circular` > …） | 「最も重大な原因」を見せられる | 順位表が恣意的で、覚えることが増える。**評価順序が観測できなくなる** |
| C | すべてのエラーを集めて返す | 情報が最も多い | エラーが値である以上、複数のエラーを保持する値の型が要る。§0.3 の表記も増える |

## 決定

**A を採用する。** 利用者の指示は「Smalltalk の仕様に合わせる」であった。

Smalltalk ではエラーは例外であり、生じた瞬間にその場で巻き戻す。この言語の
エラーは**値**であって例外ではない（要件 F-8-1。ここは覆さない）。**順序だけを
Smalltalk に揃える**と、次の規則になる。

> 式の評価は §3.6 の順序で進み、**最初に生じたエラーがその式全体の値になる。
> それ以降は評価しない。**

帰結として次が定まる。

- `(3 foo) + (1 / 0)` → `#DoesNotUnderstand`。受け手が先に評価される
- `(1 / 0) + (3 foo)` → `#DivideByZero`。**種別に強弱は無く、決めるのは順序だけ**
- `3 foo: (1 / 0)` → `#DivideByZero`。**引数は送信より先に評価される**ので、
  セレクタを理解しないと分かる前にエラーになる
- `(1 / 0) abs` → `#DivideByZero`。エラーは「セレクタを理解しない値」には変わらない
- 構文エラーは評価より前に決まるため、常に実行時のエラーより先に出る
- 評価されないブロックの中のエラーは生じない（§5.2 の遅延評価）

## 影響

- **付録 B の「複数のエラーが同時に生じたときどれが伝播するか」が解消される。**
  §3.6 の評価順序を `tests/golden/errors.txt` で観測・固定できるようになった
- §6.0 にこの規則を書き下ろす
- エラーの捕捉（未決論点 D-8、`ifError:`）を入れるなら、捕まえられるのは
  「最初のエラー」1 つである
- 評価器の実装は、エラーを値として返しつつ**後続の評価を打ち切る**必要がある。
  受け手や引数の評価結果がエラーなら、そこで返す

## 覆すとしたら

- 利用者が「式のどこが原因か」を特定できず、複数のエラーをまとめて提示する必要が
  あると判明したとき → C（エラーの集約）へ。ただし §0.3 の表記と
  ゴールデンテストの期待値がすべて影響を受ける
