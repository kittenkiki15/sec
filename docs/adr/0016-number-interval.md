# ADR-0016: 数への `to:` は区間（`Interval`）を作る

- 状態: accepted
- 日付: 2026-09-15
- 関連: 要件 F-2-7、[ADR-0007](0007-range-cell-reference-assignment.md)、仕様書 §4.3、§6.3

## 背景

付録 B に「**数の区間（`1 to: 10`）を作れるようにするか**」が未決論点として残っていた。
§4.3 は `to:` を**セル参照から範囲を作る正準形**と定めており、数へ広げるかは保留していた。

## 選択肢

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A | 入れない | `to:` の意味が 1 つに保たれる。クラスが増えない | `collect:` で数を並べる手段が無い |
| B | **入れる** | Smalltalk の `Interval` に相当し、知る利用者には自然 | `to:` が多重定義になる。クラスが 1 つ増える |

## 決定

**B を採用する**（利用者の選択）。

- **`Number to: Number` は `Interval` を返す。** 刻みは 1 で固定する
- **`Cell to: Cell` は従来どおり `Range`**（§4.3）

### `to:` は受け手で行き先が分かれる

**同じセレクタが 2 つの違うものを作る。**

| 受け手 | 引数 | 返り値 |
| --- | --- | --- |
| `Cell` | `Cell` | `Range`（セルの矩形） |
| `Number` | `Number` | `Interval`（数の並び） |

混ざった場合（`A1 to: 5`）は `#TypeError` とする。`Cell` は `to:` を自身で理解し
（§4.2 の規則 1）、引数が `Cell` でなければ型が合わない。

### 逆向きの扱いが `Range` と逆になる

**ここが最も紛らわしい。**

| | 逆向きに書いたとき |
| --- | --- |
| `Range` | **正規化する。** `B10 to: A1` は `A1 to: B10` と同じ矩形（§4.3） |
| `Interval` | **空になる。** `5 to: 1` は要素を持たない |

範囲を正規化するのは、ドラッグの向きで結果が変わらない方が表計算の期待に沿うためである
（§4.3）。一方、数の区間で `5 to: 1` を `1 to: 5` と読み替えると、**繰り返しの回数が
意図せず増える**。`1 to: n` で `n` が 0 のときに空になることは、むしろ期待される挙動である。

**この非対称は仕様書に明記し、両方をゴールデンテストで固定する。**

### 端は小数でもよい

刻みが 1 なので、上端を超えない最後の要素で止まる。`1 to: 3.5` の要素は 1・2・3 である。

## 影響

- **要件 F-2-7 のクラス一覧に `Interval` は無い。** §6.3 に足したうえで、要件から外れる
  ことを報告する（要件定義書は変更しない。クラスの追加であって既存の定義の変更ではない）
- §6.0 の値の分類に `Interval` を足す
- 付録 B から「数の区間」を外す
- `to:by:`（刻みの指定）は入れない。必要になったら足す

## 覆すとしたら

- `to:` の多重定義が利用者に混乱を与えると判明したとき → 数の区間に別のセレクタを与える
  （`1 upTo: 10` など）。`Range` 側の `to:` は §4.3 の正準形なので動かさない
