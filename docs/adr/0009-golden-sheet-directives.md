# ADR-0009: ゴールデンテストにシートの状態を与える記法

- 状態: accepted
- 日付: 2026-09-14
- 関連: [ADR-0003](0003-golden-test-format.md)（その「覆すとしたら」が想定していた拡張）

## 背景

段階 2（#4）でセル参照と範囲の仕様を書くには、`A1` に値が入った状態で式を評価する
ケースが要る。しかし ADR-0003 の形式は**式と期待値しか書けず、セルの値を与える手段が無い。**

ADR-0003 の「覆すとしたら」には、この事態を次のように予期してあった。

> 1 つのケースに複数の入力シート状態を与える必要が出て、平文では表現しきれなくなったとき
> → シート状態だけを別ファイルに切り出し、ケースから参照する形に拡張する
> （形式そのものは変えず、前置きのディレクティブを足す方向で検討する）

## 決定

**ケースの先頭に、前置きのディレクティブでセルの内容を書く。**

```text
"A1 と A2 に値が入っているとき
!A1 = 1
!A2 = 2
A1 + A2
=> 3

"セルには数式も入れられる
!A1 = 1
!B1 = =A1 + 1
B1
=> 2
```

- 行頭が `!` の行はシートディレクティブ。**式より前に置く。**
- 形は `!<セル参照> = <内容>`。最初の `=` だけが区切りで、
  **右側に数式（`=A1 + 1`）を書ける。**
- 内容は原文テキストとして保持する（要件 F-5-1）。`=` で始まれば数式。
- **ディレクティブはケースごとに独立している。** ケースをまたいで状態を持ち越さない。

### 別ファイルに切り出さなかった理由

ADR-0003 が挙げていた「別ファイルに切り出して参照する」案は採らない。
ケースとシートが離れると、**1 つのケースを読むのに 2 箇所を見る必要が生じる。**
差分でレビューできることがこの形式の利点なので、局所性を優先した。
1 つのシートを多数のケースで共有したくなったら、そのとき改めて検討する。

### `!` を選んだ理由

`!` は二項セレクタの文字ではない（§1.4）。**式が `!` で始まることはあり得ない**ため、
ディレクティブと式を字句解析なしに区別できる。

### 拒否するもの

タグと同じく、フィクスチャは誤りに気づきにくい。次はすべてエラーにする。

| 内容 | 理由 |
| --- | --- |
| 式より後のディレクティブ | 読む順序と適用順序が食い違う |
| 同じセルの重複指定 | どちらが有効か読み取れない |
| セル参照の形でない指定（`a1` `A` `1A` `Abc123` `A1:B2`） | ADR-0007 D-2 の形だけを受け付ける |
| 区切りの `=` が無い | 形式の誤り |
| 内容が空 | 空セルを表したいならその行を書かない。D-6 が決まるまで空の意味を固定しない |

## 影響

- `GoldenCase` に `sheet: ReadonlyMap<string, string>` が増えた。
  ディレクティブの無いケースでは空になる。
- `GoldenEvaluator` の型が `(source, sheet) => string` に変わった。
  評価器はまだ存在しないため、影響を受ける実装は無い。
- ケースの開始行 `line` は、ディレクティブを飛ばした**式の先頭行**を指す。
- ADR-0003 の形式は置き換えではなく**拡張**である。
  ディレクティブの無いフィクスチャはそのまま動く。

## 覆すとしたら

- 同じシートを多数のケースで共有したくなり、ディレクティブの重複が目立つとき
  → ファイル先頭の既定シートを足す（ケース側の指定で上書きする形）
- 行や列の一括指定（`!A1:A10 = ...`）が必要になったとき → 記法を足す
