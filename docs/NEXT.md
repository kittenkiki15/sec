### 段階 3（PR A）で確定させた判断（レビュー対象）

ADR にしたものが 4 件（0010 / 0011 / 0012 / 0013）。**PR A は AI レビューを 11 回受け、
10 件の指摘に対応した**（3 件が初版から残っていた仕様の穴、5 件が自分の修正の副作用、
2 件がメタ情報の書き漏らし）。0013 はその 1 回目への対応で、
**要件定義書 F-8-2 のエラー種別を 7 種から 8 種に増やしている**（`#Overflow` を追加）。
非有限値（`Infinity` `NaN`）を値として持たないという判断で、`rounded` / `truncated` が
常に整数を返す規則を保つため。

ADR にせず付録 A に入れたものは次のとおり。

- **負の数の `sqrt` は `#Overflow`。** 数の範囲・定義域の誤りを 1 つの種別にまとめた（ADR-0013）
- **`2.5 rounded` は `3`**（大きい側へ）。Smalltalk-80 の `rounded` に合わせた
- **`3 between: 5 and: 1` は `false`。** 範囲（§4.3）と違い区間は正規化しない
- **`=` `~=` は型が違ってもエラーにしない**
- **`Date` / `Sheet` は §6 に入れない。** F-2-7 は挙げているが、日付は F-2-12（優先度 S）で
  決定性の設計が別途要り、`Sheet` は数式から触れると副作用の経路になる（F-2-10）
- **アンダーフローは `0.0` に丸める**（エラーにしない）。下側には丸め先があり上側には無い
- **`min:` / `max:` は `<` `>` で定義し、同値なら引数を返す**（`1 min: 1.0` → `1.0`）
- **負のゼロは値としては残すが表記は `0.0`**

### 段階 3（PR B）で確定させた判断（レビュー対象）

**ADR-0014 で F-8-2 のエラー種別を 8 種から 9 種に増やしている**（`#SubscriptOutOfBounds`）。
要件定義書の変更は ADR-0013 に続いて 2 度目。付録 A に入れたものは次のとおり。

- **文字型は持たない。** `indexOf:` は部分文字列を取る（F-2-7 に文字が無い）
- **添字は 1 起点。** `0` は常に範囲外（Smalltalk-80 と Excel が一致）
- **`indexOf:` が見つからなければ `0`**（Smalltalk-80）
- **`asNumber` が受理するのは §2.1 の数値リテラルちょうど。** 読めなければ `nil`
- **シンボルと文字列は両向きとも等しくない**（`#foo = 'foo'` も `'foo' = #foo` も `false`）
- **シンボルは `size` を理解しない**（識別子であって文字の並びではない）

### 段階 3（PR C）で確定させた判断（レビュー対象）

ADR が 3 本（0015 / 0016 / 0017）。**要件定義書は変更していない。**

- **範囲の列挙は `Cell` を渡す**（ADR-0015）。配列は値を渡すので**要素の正体が非対称**。
  表記では見分けが付かず、`value` を送れるかどうかが唯一の手がかり
- **範囲の列挙順は行優先**
- **数への `to:` は `Interval` を作る**（ADR-0016）。`to:` が受け手で行き先を変える。
  **逆向きの扱いが `Range` と逆**（範囲は正規化、区間は空）
- **`Interval` は要件 F-2-7 のクラス一覧に無い。** 追加であって既存定義の変更ではないため、
  要件定義書は変えず §6.3 に足した
- **小数の指数表記は Smalltalk に寄せた**（ADR-0017）。**Excel は選べない** —— 大文字 `E` を
  §2.1 がセル参照との衝突を理由に拒んでいるため。**切り替えの境界だけは本書で固定**
- **`do:` は数式に入れず §7 へ。** 副作用を持てない数式では何も観測できない
- **`first` / `last` が空なら `#SubscriptOutOfBounds`。** 添字アクセスであって集計ではない

`tests/golden/consistency.test.mjs` を足した。**エラー種別が F-8-2 にあること**と、
**すべてのフィクスチャが README の割り当て表に載っていること**を検査する。
セレクタの網羅は見ていない（キーワードメッセージを構文解析器なしに切り出すと誤検出が多い）。
**M1 で評価器ができたら入れ替えること。**

### 段階 3 で先送りした論点

**残っているのは文字列と Unicode だけ**（小数の表記は ADR-0017 で決着）。未決は 2 点だけで、`size` と添字が何を 1 と
数えるか（コードポイントか書記素クラスタか）と、`asUppercase` が ASCII 外をどう写すか。
**非 ASCII のリテラルを扱えること自体は未決ではない**（§1.1 がソースを Unicode と定めて
おり、保持・比較・連結は数え方に依存しない）。**UI が実際に扱う文字を見てから決める方が
確実**なので M0 では決めない。

### 段階 2 で確定させた判断（レビュー対象）

仕様書の付録 A に一覧がある。特に次の 3 つは覆すなら ADR が要る。

- **`A1 = A2` は値の比較。** `Cell` は `=` を定義せず、ADR-0008 の委譲規則に任せる
- **範囲の表記は正準形と同じ `A1 to: B10`。** 糖衣の設定で読み方が揺れないようにするため
- **逆向きの範囲は正規化する。** `B10 to: A1` は `A1 to: B10` と同じ矩形

**数式のブロックの本体は式ちょうど 1 つ**とした（F-2-10）。文の列と一時変数を持つ
ブロックは段階 4（#6）でマクロの文法として扱う。

### 段階 1 で確定させた判断（レビュー対象）

仕様書 `docs/02-language-spec.md` の付録 A に一覧がある。特に次の 3 つは覆すなら ADR が要る。

- **指数の `e` は小文字だけ。** `1E3` は `E3` がセル参照の形と衝突するため `#Syntax`
- **`5.` は小数として認めない。** マクロの文区切り `.` と紛れるため
- **負のリテラルと二項の `-` は直前のトークンで区別する。** `3 -4` は `-1`

段階 1〜2 のフィクスチャが先に使ってしまったセレクタのうち、**`abs` / `negated` / `squared` /
`max:` / `min:` / `between:and:` / `/` / `>` は §6.1 に入れた。** 残るは `size`（§6.2 の
`String`、PR B）と `sum`（§6.3 の `Range`、PR C）。**PR C でセレクタの網羅を機械的に検査する
テストを入れる**予定（仕様書の表に無いセレクタがフィクスチャに現れたら落とす）。
