# ゴールデンテスト

このディレクトリの `*.txt` が**言語仕様の実体**です。
実装より先にここへケースを足し、それを緑にする形で開発を進めます。

形式の決定理由は [ADR-0003](../../docs/adr/0003-golden-test-format.md)、
ハーネスは `packages/core/src/testing/golden.ts` にあります。

## 形式

```text
"行頭が二重引用符の行はコメント（Smalltalk のコメントに合わせています）

3 + 4 * 2
=> 14

"式も期待値も複数行に書けます
| a |
a := 3.
^ a + 1
=> 4
```

- 空行がケースの区切りです。
- ケース内で最初に現れる `=>` で始まる行から後ろが期待値です。
- 行末の空白は無視されます。

## シートの状態を与える

セルに値が入った状態で式を評価したいときは、**式より前に**シートディレクティブを書きます
（[ADR-0009](../../docs/adr/0009-golden-sheet-directives.md)）。

```text
"A1 と A2 に値が入っているとき
!A1 := 1
!A2 := 2
A1 + A2
=> 3

"セルには数式も入れられる。最初の := が区切りなので、右側に = を書ける
!A1 := 1
!B1 := =A1 + 1
B1
=> 2
```

- 形は `!<セル参照> := <内容>`。内容は原文テキストとして保持され、`=` で始まれば数式です。
- **区切りはセルへの代入と同じ `:=`** です（ADR-0007 D-3 の `B14 := total`）。
  `!A1 := 1` を「A1 に 1 を代入する」と読めるようにするためで、`=` だけの指定はエラーです。
- **指定はケースごとに独立**です。ケースをまたいで状態は持ち越しません。
- 次はすべてエラーになります。式より後のディレクティブ、同じセルの重複指定、
  セル参照の形でない指定、区切りの `:=` が無いもの、区切りが `=` だけのもの、内容が空のもの。
- **空のセルを表したい場合は、その行を書きません。** 空セルの値は `nil` で
  （[ADR-0010](../../docs/adr/0010-empty-cell-value.md)）、指定の無いセルがそれを表します。
  内容が空の指定は受け付けません。

## 規則

- 構文や組み込みセレクタを追加・変更したら、**必ず対応するケースを追加・更新**してください。
- **実装を通すために期待値を書き換えないでください。** 期待値の変更は仕様変更であり、ADR が必要です。
- 境界値とエラーケース（ゼロ除算、型不一致、空セル、循環参照）を意識して入れてください。

## 形式の検証

`format.test.mjs` が、このディレクトリの `*.txt` をすべて `parseGoldenFile` で解析できることを
検証します。`consistency.test.mjs` は、**期待値に現れるエラー種別が要件 F-8-2 に定められて
いること**と、**すべての `*.txt` が上の割り当て表に載っていること**を検証します。

**評価器が無い間、フィクスチャに対して走るのはこの 2 つだけです。**
期待値が合っているかは検証しません（評価器ができてから）。

セレクタの網羅は検査していません。キーワードメッセージは `detect:ifNone:` のように連結して
1 つのセレクタになるため、構文解析器なしには正しく切り出せず、誤検出の方が害になります。
評価器ができたら M1 で入れ替えます。
