"エラーの伝播順序。仕様書 §6.0 と ADR-0011 に対応する。
"
"評価は §3.6 の順序（受け手 → 引数を左から右 → 送信）で進み、
"最初に生じたエラーがその式全体の値になる。それ以降は評価しない。
"エラーの種別に強弱は無く、決めるのは順序だけ。
"
"このファイルは、付録 B が「これが決まるまで §3.6 の評価順序を固定できない」
"としていた論点そのものを固定する。

"--- 受け手が引数より先 ---

"受け手と引数の双方がエラーになるなら、受け手のエラーが返る
(3 foo) + (1 / 0)
=> #DoesNotUnderstand

"順序を入れ替えれば、返るエラーも入れ替わる。種別に優先順位は無い
(1 / 0) + (3 foo)
=> #DivideByZero

"--- 引数は左から右 ---

3 between: (1 / 0) and: (3 foo)
=> #DivideByZero

3 between: (3 foo) and: (1 / 0)
=> #DoesNotUnderstand

"--- 引数は送信より先 ---

"引数はメッセージを送る前に評価される（§3.6）。セレクタを理解しないと分かるのは
"送信のときなので、引数のエラーの方が先に出る
3 foo: (1 / 0)
=> #DivideByZero

"引数が正常なら、送信の段階で #DoesNotUnderstand になる
3 foo: 1
=> #DoesNotUnderstand

"引数が複数でも同じ。最初にエラーになった引数で打ち切る
3 foo: (1 / 0) bar: (2 baz)
=> #DivideByZero

"--- 二項は左から右（§3.5） ---

"(1 + (3 foo)) を先に評価するので、右端の 1 / 0 までは進まない
1 + (3 foo) + (1 / 0)
=> #DoesNotUnderstand

"--- エラーに更にメッセージを送ろうとしても、そこで打ち切られている ---

(1 / 0) abs
=> #DivideByZero

"エラーになった受け手に更にメッセージを送っても、最初のエラーのまま。
"エラーが「セレクタを理解しない値」に変わるわけではない
(1 / 0) abs squared
=> #DivideByZero

"--- 構文エラーが最も先 ---

"構文エラーは評価より前に決まるので、実行時のエラーより先に出る
(1 / 0) +
=> #Syntax

(1 / 0) max:
=> #Syntax

"--- 評価されなければエラーにならない ---

"選ばれなかった側のブロックは評価されない（§5.2）ので、エラーも生じない
true ifTrue: [1] ifFalse: [1 / 0]
=> 1

false ifTrue: [1 / 0] ifFalse: [2]
=> 2

"ブロックを作るだけではエラーにならない
[1 / 0]
=> aBlock

"条件式の受け手がエラーなら、どちらのブロックも評価されない
(1 / 0) ifTrue: [1] ifFalse: [2]
=> #DivideByZero

"ブロックの中のエラーは、value を送って初めて生じる
[1 / 0] value
=> #DivideByZero

"--- セルの側のエラー ---

"数式のセルがエラーなら、それを参照した式もそのエラーになる（F-8-1）
!A1 := =1 / 0
A1 + 1
=> #DivideByZero

"受け手のセルが先に評価される
!A1 := =1 / 0
!B1 := =2 foo
A1 + B1
=> #DivideByZero

"入れ替えれば返るエラーも入れ替わる
!A1 := =1 / 0
!B1 := =2 foo
B1 + A1
=> #DoesNotUnderstand

"受け手のセルは引数より先に解決される。受け手の値がエラーなら引数に到達しない（§4.2）
!A1 := =1 / 0
A1 + (2 foo)
=> #DivideByZero

"--- 空セルを含む算術（ADR-0010） ---

"指定の無いセルは空で、値は nil。委譲（§4.2）に例外を作らないので算術はエラーになる。
"Excel は両方 1 を返すため、ここは意図的な乖離。
"受け手が nil なら、nil が + を理解しない
A1 + 1
=> #DoesNotUnderstand

"引数が nil なら、Number は + を理解するので型の誤りになる。向きで種別が変わる
1 + A1
=> #TypeError

"nil を直接書いても同じ。空セルだけの特別扱いは無い
nil + 1
=> #DoesNotUnderstand

1 + nil
=> #TypeError

"ifNil: なら受け手が nil でも通る（§5.2）
A1 ifNil: [0]
=> 0

"存在しないセルの参照（§4.1）も同じ順序に従う
A0 + (1 / 0)
=> #Ref

"受け手が先にエラーになるなら、存在しない参照に到達しない
(1 / 0) + A0
=> #DivideByZero

"循環参照のセル（§4.2）も同じ
!A1 := =A1
A1 + (1 / 0)
=> #Circular

"裸の識別子の #Ref（§4.2）も同じ
foo + (1 / 0)
=> #Ref
